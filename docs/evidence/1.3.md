### Transfer & Importer Details
- **Import:** Copies v1 project YAMLs into target storage (File or Mongo). Scans `.env` for known provider API keys (via `PROVIDER_REGISTRY`), encrypts them into the vault, and reports other env variables by name only.
- **Export:** Writes a v1-compatible project directory. Missions restore original filenames (so `agentos run --mission <name>` works). Stored tools, MCP servers, and provider configs export to `.agentos/*.json`. Credentials are NEVER exported.
- **File Checkpoint Laziness:** The File checkpoint repository opens `run_history.db` on first read/write, avoiding spurious DB creation during project reading.

## (d) Known gaps
- Non-provider environment variables in `.env` are logged by name in the transfer report but not persisted in the vault.
- MCP plugins (`mcp_plugins/`) and execution checkpoints/history are intentionally not migrated by `import_project` (documented lossy transfer boundaries).
- UI vault management and credential viewing components arrive in Phase 1.4.

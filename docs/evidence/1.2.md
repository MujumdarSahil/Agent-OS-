### Repositories (spec Phase 1 list)
| Repository | File backend (Standalone) | Mongo backend (Platform) |
|---|---|---|
| agents | `agents/*.yaml` via `project_ops` (v1 bytes) | `agents` |
| squads (crews + roles) | `crews/*.yaml`; plain crews byte-identical to v1, `roles` is an extra key v1 ignores | `squads` |
| missions | `missions/*.yaml` via `project_ops` | `missions` |
| tools | stored: `.agentos/tools/*.json`; v1 `tools/*.py` listed read-only (`origin="project"`) | `tools` |
| MCP servers | `.agentos/mcp_servers/*.json` | `mcp_servers` |
| provider configs (order/enabled/timeout) | `.agentos/providers/*.json` | `provider_configs` |
| credentials (ciphertext only) | `~/.agentos/vault.json` | `credentials` |
| runs | `.agentos/runs/*.json` | `runs` |
| checkpoints | the v1 `checkpoints/run_history.db` via `SQLiteCheckpointStore` | `checkpoints` (same semantics) |
| events (append-only, gap-free `seq`) | `.agentos/events/*.jsonl` | `events` + atomic `event_counters`, unique `(run_id, seq)` |

Decisions worth reviewing:
- **Stored tool code never goes into `tools/`**, because the v1 runtime (`build_squad_from_project`) imports every `tools/*.py`. Writing UI-supplied code there would execute it, breaking "stored code is not executed outside a sandbox".
- **Missions got a repository** although the spec list omits them: a mission is what links a crew to its tasks, so the importer (1.3) needs it.
- **The checkpoint repository mirrors `CheckpointStore`** (same four methods, async) instead of a new shape, so the squad runtime can later be pointed at Mongo without semantic drift.
- **File names are checked against path traversal** (`../x`, `a/b`, `.hidden` rejected). The v1 `project_ops` helpers do not check this; that pre-existing gap is unchanged for v1 callers.
- PyMongo async status was confirmed in MongoDB's docs: `AsyncMongoClient` is GA, and Motor has been deprecated since 14 May 2025 ([migration guide](https://www.mongodb.com/docs/languages/python/pymongo-driver/current/reference/migration/)).

## (d) Known gaps
- **CI not run, no PR:** `gh` is not authenticated and nothing is pushed; the `mongo-live` CI job has never run on GitHub. It mirrors the local commands, but that is not proof.
- **Nothing uses the repositories yet.** The server routes, RunManager and squad runtime still use their v1 paths; wiring happens in 1.3 (importer) and 1.4 (API/UI). RunManager events are still in-memory only.
- **File event sequencing is single-process** (in-process lock). Fine for Standalone; Platform uses Mongo's atomic counter.
- **The vault does no crypto yet:** the credentials repository only stores already-encrypted records. AES-256-GCM encryption arrives in 1.3.
- MCP stdio allowlist and RBAC are not enforced here (records default to `enabled=False`); enforcement is Phase 3.
- The keyfile/auth setup was verified on Docker Desktop (Windows, linux/amd64 image). It has not been verified on Linux CI yet (same caveat as the first item).

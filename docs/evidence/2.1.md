## (a) What Changed

Sub-Milestone 2.1 introduces versioned flow management, an in-process leasing queue, distributed flow workers with lease fencing safety, REST/WebSocket run execution and approval endpoints under `/api/v2/flows`, and dead-letter fault isolation.

### 1. Storage Layer (`agentos/storage/`)
- **Data Models (`agentos/storage/models.py`):**
  - Added `FlowRecord` with fields: `id`, `name`, `status` (`draft` | `published` | `archived`), `version`, `entrypoint`, `nodes`, `edges`, `loops`, `content_sha256`, `policy_hash`, `created_at`, `updated_at`, `published_at`, `archived_at`.
  - Added `flow_id`, `flow_version`, and `current_lease_id` to `RunRecord`.
  - Added `lease_id` to `EventRecord`.
- **Repository Interfaces & Protocols (`agentos/storage/ports.py`):**
  - Defined `FlowRepository` protocol (`get_draft`, `put_draft`, `get_version`, `list_versions`, `list_flows`, `publish`, `delete_flow`, `archive_flow`).
  - Added `FencingTokenError` exception for stale lease rejections.
  - Added `lease_id: Optional[str] = None` to `EventRepository.append()`.
  - Added `flows: Optional[FlowRepository] = None` to `Storage`.
- **File Storage Backend (`agentos/storage/file/__init__.py`):**
  - Stored under `<project>/.agentos/flows/<flow_id>/draft.json` and `v<version>.json`.
  - **Atomic Version Assignment:** Uses `os.open` with `os.O_CREAT | os.O_EXCL` in an increment retry loop to ensure collision-free sequential version allocation without race conditions or lost versions.
  - **Deletion Guard:** Rejects `delete_flow()` with `ValueError` (409 Conflict) if any published versions exist.
  - **Archive:** Transitions draft status to `archived` without deleting historical versions.
  - **Fencing Token Checker:** Rejects `append()` with `FencingTokenError` if `_fencing_checker` rejects the lease.
- **MongoDB Storage Backend (`agentos/storage/mongo/__init__.py`):**
  - Stored in `db.flows` with compound unique index on `("flow_id", "version")` and partial filter `{"record_type": "version"}`.
  - Atomic version assignment via atomic counter documents.
  - Deletion guard and explicit archive endpoint support.
  - Fencing token checker hook in `MongoEventRepository.append()`.

### 2. Queue Backend & Fencing Token Protocol (`agentos/queue/`)
- **Queue Interface & Data Models (`agentos/queue/ports.py`):**
  - `QueueJob` carrying `job_id`, `run_id`, `flow_id`, `version`, `inputs`, `status` (`queued`, `leased`, `completed`, `failed`, `waiting`, `dead_letter`), `lease_id`, `leased_until`, `worker_id`, `attempts`, `max_attempts`, `last_error`, `created_at`.
  - `QueueBackend` protocol defining `enqueue`, `lease`, `renew_lease`, `complete`, `fail`, `release_for_waiting`, `reenqueue`, `get_job`, `get_job_by_run_id`, `validate_lease`.
- **In-Process Implementation (`agentos/queue/in_process.py`):**
  - Thread- and async-safe locking around job states and lease timers.
  - **Monotonic Lease Deadlines:** Uses `time.monotonic()` for all lease expiration and deadline calculations to protect against wall-clock skew.
  - **Fail-Closed Lease Checks in Every State:** `complete()` and `fail()` require an active lease match in every state, including `waiting`.
  - **Fail-Closed Unregistered Runs:** `validate_lease()` for unknown runs returns `False` if `lease_id` is supplied (fail closed), and `True` only when `lease_id=None` (unleased direct engine use).
  - **Max Attempts & Dead-Letter Isolation:** Increments `attempts` on every lease. After `max_attempts` (default 3), transitions the job to `dead_letter`, halts re-leasing, and marks the run failed with `max_attempts_exceeded`.

### 3. Flow Engine & Flow Worker (`agentos/flows/`)
- **Worker Execution Loop (`agentos/flows/worker.py`):**
  - Leases jobs and maintains a background heartbeat loop renewing the lease every `lease_timeout / 3`.
  - Decides run vs. resume strictly from event history (`run_started` in event log), independent of attempt counts.
  - When reaching an approval node (`WAITING`), releases worker lease immediately to free worker resources.
  - Halts immediately upon `FencingTokenError` if its lease has been superseded.
- **Engine Lease Fencing (`agentos/flows/engine.py`):**
  - `_check_fencing()` is always active: fails closed (`FencingTokenError`) if `lease_id` is present but `fencing_checker` is missing or rejects.
  - Validates fencing before invoking sink transports (`transport.send`) and updating run records.
  - Mediates agent tool calls through `AgentOSToolProxy` with `lease_id` and `fencing_checker` attached.
  - Treats manual trigger inputs as `untrusted` by default (`MANUAL_TRIGGER_SPEC`).
  - Supports idempotent approvals and clean rejection without invoking sink transports.
- **Agent Tool Proxy Fencing (`agentos/flows/proxy.py`):**
  - Intercepts all agent tool calls with active fencing validation before calling external transports and appending events.

### 4. REST & WebSocket API (`agentos_server/routes_v2/flows.py`)
- Full CRUD for flows under `/api/v2/flows`:
  - `GET /api/v2/flows`, `POST /api/v2/flows`: List and draft creation.
  - `GET /api/v2/flows/{id}`, `PUT /api/v2/flows/{id}`, `DELETE /api/v2/flows/{id}`: Draft retrieval, updates, and deletion (409 Conflict guard if published versions exist).
  - `POST /api/v2/flows/{id}/archive`: Archival endpoint.
  - `POST /api/v2/flows/{id}/publish`: Publish gate executing `StaticFlowAnalyzer` with `SecurityPolicy`. Violations return 400 with a detailed violation list.
  - `GET /api/v2/flows/{id}/versions`, `GET /api/v2/flows/{id}/versions/{v}`: Immutable version query.
  - `POST /api/v2/flows/{id}/runs`: Enqueue a flow run (inputs tagged `untrusted` by default).
  - `GET /api/v2/flows/{id}/runs`, `GET /api/v2/flows/{id}/runs/{run_id}`: Run state query.
  - `GET /api/v2/flows/{id}/runs/{run_id}/events`: Long-polling event query with `after_seq`.
  - `WS /api/v2/flows/{id}/runs/{run_id}/events`: Token- and Host-authenticated WebSocket event stream.
  - `POST /api/v2/flows/{id}/runs/{run_id}/approve`: Operator approval/rejection endpoint.
- **Server Startup Recovery (`agentos_server/app.py`):**
  - Server lifespan scans storage on boot to identify runs left in `queued` or `running` state and automatically re-enqueues them into the queue backend.

### 5. Use Case 03 (`examples/usecases/03-flow-queue-worker/`)
- Demonstrates:
  - Benign leased execution and exactly-once dispatch.
  - Worker failover and fencing token safety under lease expiration.
  - Poison-pill bounded retries and dead-letter isolation.
- Automated CI test in `tests/ci/test_usecase_03.py`.

## (d) Known Gaps and Exclusions
- Redis queue backend is planned for Sub-Milestone 2.2 (Standalone uses thread/async safe `InProcessQueueBackend`).
- Full RBAC for multi-user governance lands in Phase 3. In Phase 2, administrative configuration and publish gates use the local API token.

## (e) How the Owner Can Reproduce the Demo
```bash
python examples/usecases/03-flow-queue-worker/run.py --mode all
```
The command executes all three scenarios:
1. Benign draft creation, static analyzer gate publication, queue leasing, worker execution, and exactly-once send.
2. Worker lease expiration, failover to Worker 2, and rejected late append via `FencingTokenError`.
3. Poison-pill run triggering bounded retries (3 attempts), automatic dead-letter queue isolation, and failed run status update.

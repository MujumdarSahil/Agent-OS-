## (a) What changed

### Architectural Overview
Sub-Milestone 1.5 delivers the AgentOS 2.0 Flow Engine spike and establishes the architecture for secure, event-sourced workflow orchestration in AgentOS 2.0:
1. **Flow Engine Core (`agentos/flows/`):**
   - Implemented a lightweight, native async DAG engine with explicit bounded loop nodes (`LoopNode`), barrier join synchronization, and cycle detection.
   - Information Flow Control (IFC) with $\langle \text{Integrity}, \text{Confidentiality}, \text{Provenance} \rangle$ metadata labels on every edge and node input/output (`agentos/flows/labels.py`).
   - Unified Security Policy & Sink Rule Engine (`agentos/flows/policy.py`) evaluating integrity requirements, recipient domain allowlists, and confidentiality egress restrictions across both publish-time static analysis and runtime monitoring.
   - Append-only event-sourced execution reusing AgentOS 1.2 storage ports (`Storage.runs`, `Storage.events`, `Storage.checkpoints`) without introducing new storage engines or external daemons.
   - Durable waiting states: flows pause to `RunStatus.WAITING` (freeing workers/memory) on approval gates and uncommitted sink intents, resuming cleanly via `approve()` or `resume()`.
   - Tool Proxy mediation (`agentos/flows/proxy.py`): intercepts all CrewAI ReAct and native tool calls, enforces pinned author arguments, and enforces idempotency via content-hashed keys. Unknown tools fail closed.
2. **Hardened CrewAI Integration:**
   - Scripted deterministic LLMs for both ReAct and native function-calling paths (`CrewAIScriptedLLM`, `NativeScriptedLLM`).
   - Forced agent hardening: `cache=False`, `allow_delegation=False`, `allow_code_execution=False`, rejecting configs attempting to pass unmediated MCP servers, memory, or knowledge sources.
3. **Use Case #1 (`examples/usecases/01-email-summary-exfil/`):**
   - End-to-end runnable usecase demonstrating protection against prompt injection exfiltration attacks.
   - Includes benign and attack inputs, scripted LLM responses, reproduction script `run.py`, and automated CI verification in `tests/ci/test_usecase_01.py`.
4. **ADR 0001 Decision:**
   - Completed desk evaluation of LangGraph and Temporal against 10 restored architectural criteria.
   - Formally accepted **Option 3: Custom Async DAG** (status: *Accepted (pending owner approval)*).
5. **Standing Rule 11 in `CLAUDE.md`:**
   - Added standing requirement: every user-facing feature ships with a use case under `examples/usecases/NN-name/` with benign and attack inputs where security-relevant, run in CI in MOCK mode.

## (e) Use Case 01 Demonstration & Reproduction

Use case #1 is located at `examples/usecases/01-email-summary-exfil/`.

### Scenario
An incoming webhook accepts customer bug reports and support requests. An agent summarizes the ticket and uses `send_email` to notify the support engineering team at `support@corp.local`.
- **Benign Input (`inputs/benign.json`):** A legitimate database connection pool issue. The agent summarizes the problem and emails the pinned address `support@corp.local`. Execution succeeds with exactly 1 send.
- **Attack Input (`inputs/attack.json`):** A prompt injection payload instructing the model to exfiltrate database credentials and send the email to `attacker@evil.com`. The Tool Proxy detects that the model attempted to override the pinned recipient with untrusted arguments; the call is blocked, 0 emails are sent, and the full event provenance trace is emitted to audit logs.

### Reproduction
```powershell
# Run benign flow
python examples/usecases/01-email-summary-exfil/run.py --input benign

# Run attack flow
python examples/usecases/01-email-summary-exfil/run.py --input attack
```

## (f) ADR 0001 Decision & Known Gaps

### ADR Decision Status
`docs/adr/0001-flow-engine.md` status has been updated to **Accepted (pending owner approval)**. The Custom Async DAG architecture was selected because:
1. It runs in-process with zero extra daemons in Standalone mode (unlike Temporal).
2. It reuses AgentOS 1.2 storage ports (`Storage.runs`, `Storage.events`, `Storage.checkpoints`) directly without duplicate event logs.
3. It natively attaches Information Flow Control labels to all edge values without the channel reducer complexity of LangGraph.
4. It provides publish-time static verifiability over declarative definitions and runtime fail-closed tool mediation.

### Known Gaps & Next Steps
- Subprocess thread interruption: Blocking CrewAI calls executed in `asyncio.to_thread` cannot be cancelled mid-execution if a node times out (documented Python limitation; downstream execution is stopped, and the engine aborts the run).
- Interactive human approval CLI / UI: Approval nodes pause flows to `RunStatus.WAITING`; resumption currently uses the in-process `FlowEngine.approve()` API, which will be wired to the REST API / UI in Phase 2.0.

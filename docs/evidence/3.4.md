## Design decisions (written before implementation)

### Where things live
- Domain: `agentos/access/` (models, passwords, permissions, service, store). No FastAPI or Mongo imports
  (ports and adapters). File documents reuse `agentos/notify/store.py:FileDocs`; Mongo reuses
  `agentos/storage/mongo/notify.py:MongoDocs` plus unique indexes.
- Server: `agentos_server/access_mw.py` (principal, CSRF, permission check), `agentos_server/permissions_table.py`
  (route -> permission), `agentos_server/routes_v2/access.py` (auth, users, tokens, legacy token).

### Data model
| Record | Fields |
| --- | --- |
| User | `id` (uuid4), `username`, `username_lower` (unique; `[a-z0-9._-]{3,64}`, case-insensitive), `display_name`, `role` (viewer/approver/builder/admin), `disabled`, `created_at`, `updated_at`, `password_hash`, `password_changed_at` |
| Session | `id` = sha256(session id) (the raw id is never stored), `user_id`, `created_at`, `last_seen`, `ip`, `user_agent` (truncated) |
| ApiToken (PAT) | `id`, `user_id`, `name`, `token_hash` = sha256(token), `prefix` (display only), `created_at`, `expires_at` (required, 1..365 days, default 90), `last_used_at`, `revoked_at` |
| Access settings | `legacy_token_disabled` |

File backend: `<project>/.agentos/state/access_users.json`, `access_sessions.json`, `access_tokens.json`,
`access_settings.json` (atomic writes). Mongo (Platform): `users`, `sessions`, `api_tokens`, `access_settings`.

### Password hashing
- `hashlib.scrypt` (Python stdlib; no new dependency, no SBOM change) with OWASP parameters **N=2^17, r=8, p=1**,
  16-byte random salt, 32-byte key. Stored as `scrypt$17$8$1$<salt b64>$<key b64>` so parameters can be raised
  later. argon2id was the alternative; it needs a native dependency (argon2-cffi), so scrypt is the safer choice here.
- Rules: length 12..256, not in a built-in list of common passwords (case-insensitive), not equal to the username.
- About 128 MiB of memory per hash: hashing runs in a worker thread behind a semaphore of 2 so a burst of logins
  cannot exhaust memory.
- Tests make it cheaper only by monkeypatching the module constant; there is **no environment knob** that could
  weaken production hashing.
- Passwords never appear in logs, audit details, errors or responses.

### Sessions
- Session id: `secrets.token_urlsafe(32)` (256 bits). Only its sha256 is stored, so a leaked store gives no session.
- Cookie `agentos_session`: `HttpOnly`, `SameSite=Strict`, `Path=/`, and `Secure` when the request is HTTPS.
- Idle timeout 12 h, absolute timeout 7 days. `last_seen` is written at most once a minute.
- Logout revokes the current session. Changing your own password revokes all your other sessions. An admin
  password reset revokes all of that user's sessions; disabling a user revokes all sessions and tokens.

### CSRF
A cookie-authenticated state-changing request (POST, PUT, PATCH, DELETE) needs all three:
1. a valid session cookie;
2. an `Origin` header (or `Referer` when Origin is absent) whose host is localhost/127.0.0.1 (same rule as the
   existing `verify_origin`); none present = refused;
3. the header `X-AgentOS-CSRF` equal to a **per-session** token: HMAC-SHA256(key derived from the master key,
   session hash). The UI gets it from `GET /api/v2/auth/me` and keeps it in memory.

**Safer than asked:** the prompt asked for "a custom header sent by the UI". A fixed header only works because
of browser CORS rules; a per-session secret value also holds if a CORS setting is ever loosened, at no extra
cost. Bearer requests (PATs, legacy token) are not ambient credentials, so CSRF does not apply to them.

### Roles and permission matrix (deny by default)
Capabilities: `public` (no login), `self` (any logged-in user, own account), `read`, `approve`, `build`, `admin`.

| Role | Capabilities |
| --- | --- |
| viewer | read |
| approver | read, approve |
| builder | read, build |
| admin | everything |

- Every `/api` route (47 v1, 74 v2, plus the new ones) has exactly one entry in
  `agentos_server/permissions_table.py`. The middleware resolves the matched route template; **a route with no
  entry is refused (403) for everyone, admins included**. A test walks the full route table and fails if any
  route has no entry; the per-role allow/deny test matrix is generated from the same table.
- read: GET on flows, versions, runs, events, run usage, usage, overview, alerts, alert rules, node specs, agents,
  squads, tools, schedules, webhooks (no secrets in these bodies), providers and fallback (no keys), v1 GETs,
  both WebSocket streams.
- approve: approve or reject a run; acknowledge an alert.
- build: flow create/edit/delete/archive/publish (the static check still decides), start runs, agents, squads,
  tools (stored code is never executed), schedules, webhook triggers (incl. secret rotation), v1
  builder/agents/crews/missions/runs/templates, packaging build and verify.
- admin: vault, provider writes and connection tests, billing plans, v1 provider keys, MCP servers (also GET:
  it shows commands and env names) and tool review, notification channels, alert rule changes, budgets,
  audit log (list, verify, export), governance policy changes, v1 MCP plugin create, packaging sign/install,
  users, the legacy token.
- Enforcement is server-side only; the UI only hides or disables what the server would refuse anyway.

### Separation of duties (optional, default off)
`security.separation_of_duties: true` in `agentos.config.yaml` (admin configuration, like the other security
settings). Publishing records `published_by` on the flow version; with the flag on, the user (or token) who
published a version cannot approve or reject runs of it (403).

### Login
- One generic error ("Invalid username or password") for an unknown user and a wrong password. An unknown
  username is checked against a dummy scrypt hash made at startup, so both paths cost one scrypt.
  A disabled account also gets the generic error.
- Rate limit with backoff, per IP + username and per IP: after 5 failures, wait 1 s, 2 s, 4 s ... up to 15 min
  (HTTP 429 with `Retry-After`). Success resets the IP + username counter.
- Failed logins go into the audit log aggregated per minute (source `login`, count, no username), like the 3.1
  auth-failure entries. Successful logins are audited with the user as actor.
- Known gap: the limiter is in memory, per process.

### API tokens (PATs) for scripts and the CLI
- `aos_pat_` + 256 random bits, shown once at creation, stored as sha256. Name and expiry required.
- Accepted as `Authorization: Bearer <pat>` and as the WebSocket subprotocol `agentos.token.<pat>`.
- Effective role = the owner's **current** role (a demoted user's tokens are demoted too). Expired, revoked, or
  owner disabled -> 401. Users manage their own tokens; admins can list and revoke anyone's.

### Bootstrap
- `GET /api/v2/auth/status` (public): `{setup_required, version}`.
- `POST /api/v2/auth/setup` (public route): works **only while no user exists** and **requires the existing local
  API token** (`Authorization: Bearer`), so nobody else on the network can claim admin. Creates the first admin
  and logs them in.
- CLI: `agentos users create-admin` (password read without echo, written through the same service).

### Compatibility with the current token
- The existing `api.token` (or `AGENTOS_API_TOKEN`) keeps working as a **bootstrap-admin token** (principal
  `legacy-local-token`, role admin). `send_webhook.py`, the demo script and CI keep working unchanged.
- Settings shows it as "Legacy local token". An admin can rotate it (new value shown once; refused with 409
  when it comes from `AGENTOS_API_TOKEN`, which the server cannot change) or disable it. Both are audited.
  Disabling is refused while no enabled admin user exists (it would lock everyone out).
- `/hooks/*` stays HMAC-only; its code path is not touched.
- The token-in-URL UI login (`#token=`) is replaced by the login page. The startup banner no longer prints the
  token; it prints the UI address and the token file path.

### Audit
- `actor` = the username, `token:<token name>@<username>`, or `legacy-local-token` (was fixed "local-admin").
- New actions: login success, failed logins (aggregated), logout, user create/update/disable/role change,
  password change and reset, token create/revoke, legacy token rotate/disable/enable.

### Runs and approvals
- `FlowEngine.approve(..., actor=None)` (new optional argument; v1 and the use cases are unchanged) records
  `decided_by` = `{user_id, username}` in the `approval_decision` event. Starting a run records `started_by`.
  The approval card shows who decided.

### Part 0 decisions
- `.env` is loaded in one place, `agentos/core/dotenv_loader.py`, called at server and CLI startup; it honours
  `AGENTOS_SKIP_DOTENV`. No import-time `load_dotenv()` remains in `agentos` or `agentos_server`.
- MOCK mode: agent and llm nodes always go through `AgentOSRouterLLM`; in MOCK mode the router answers with a
  deterministic scripted model (`agentos/llm/mock_model.py`) and never calls LiteLLM, so `llm_call` events,
  budgets and run limits still apply (cost 0). Quarantined extraction already used an offline mock.
- Ollama health is a real HTTP check against the configured base URL (1.5 s timeout); MOCK mode says
  "not checked" rather than "healthy".

### Anything in the prompt I consider unsound, and what I chose
- "custom header sent by the UI" for CSRF: replaced by a per-session HMAC header (see CSRF).
- "builder: viewer + ... publish": builders do not get approve (as written); the separation-of-duties flag is
  still useful for admins, who have both.
- Showing the legacy token in Settings: Settings shows only its status and source, never the value (rule 6);
  the value is shown once after a rotation.

### Implemented differently from the design above (and why)
- **CSRF**: as designed (per-session HMAC header + allowed Origin). Public state-changing routes (login, setup)
  additionally refuse a cross-site `Origin`.
- **API tokens cannot create tokens, change passwords or log out**: token management needs a browser session, so a
  leaked token cannot extend itself.
- **Failed logins in the audit log**: action `auth.login_failed`, aggregated per minute and per source (`ui`/`api`),
  no username. (The 3.1 audit schema only allows known sources, so "login" is the target, not a new source.)
- **npm version**: `ui/package.json` uses `2.0.0-a1` because npm requires semver; it is the same release as Python's
  PEP 440 `2.0.0a1` (shown in the footer from the server).
- **CrewAI telemetry** is now off by default (`CREWAI_DISABLE_TELEMETRY=true` unless set). Found by the new egress
  guard: even with the model path fixed, CrewAI tried to reach `telemetry.crewai.com`. Safer default; documented.
- **Startup banner and launcher** no longer print or open a token URL (rule 6); they print the UI address and the
  token file path.
- **started_by** is stored on the run record (set by the start route) and copied into the `run_started` event.

  3.3 report records a similar read. **Suggested follow-up:** a code guard that refuses to start when

  because it touches every startup path.

  job. MongoDocs has no unique index; username uniqueness relies on the atomic claim document (tested LIVE in CI).

  - The MOCK `llm` node output is now the scripted answer (`Final Answer: ...`) instead of `Completion for: <prompt>`,

  - `GET /api/v2/mcp-servers`, `/notify/channels`, `/vault/keys` and `/audit*` need the admin role.
  - The v1 `/api/*` routes keep their paths, but each now needs a role; the legacy token (admin) keeps scripts
    working.

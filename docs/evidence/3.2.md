# 3.2 evidence: usage, cost and budgets (plus three gaps from the 3.1 review)

Branch `feature/agentos-2.0-phase3.2-usage`, cut from `2.0` at `76cef97` (3.1 merged). All results are **MOCK**
unless labelled LIVE.

## Design decisions (written before the implementation)

### 0a. Audit log deletion must not read as "empty"
- **A second, independent anchor** of the head, `{seq, hash, mac}`, keyed with the same audit HMAC key (the MAC
  input is `"anchor|<seq>|<hash>"`, so a head can't be replayed as an anchor). It's stored in the **main
  storage, not the audit folder**:
  - **File:** `<project>/.agentos/state/audit_anchor.json`, written atomically (fsync + rename).
  - **Mongo:** its own collection, `audit_anchor`, with `_id: "anchor"` and a conditional update that only
    moves forward.
- **Write order on every append:** entry → head → anchor. A crash in between only leaves the anchor *behind*
  the log, which is allowed.
- **`verify()` checks the anchor after the chain and head:**
  - anchor MAC invalid → `broken: audit anchor is invalid`;
  - log missing, or its last seq is below the anchor's, or the entry at `anchor.seq` has a different hash →
    `broken: audit log deleted or rolled back (anchor at seq N)`, at `first_broken_seq = N`;
  - anchor missing but log or head present → `broken: audit anchor missing`;
  - log, head and anchor all missing → `empty`.
- **Unsound part, written down:** "empty only on a fresh install" can't be proven from the files alone. If
  someone deletes the audit folder *and* the anchor in the state store, it looks fresh. Two separate places
  must be deleted, which is the improvement. A third anchor outside the machine is the external-anchor item
  that stays in Gaps.
- **UI:** a broken status (any reason) shows in red on the badge and in the Overview footer, with the reason as
  the badge tooltip; that already happens for every `broken` status.

### 0b. Agent tools accepted by the server = what the picker offers
- **`ToolCatalog.resolve(name)`** accepts a bare (non-MCP) name only if it's in `AGENT_TOOL_TYPES` (`calculator`,
  `fetch_url`, `send_email`). Any other NodeSpec type (`approval`, `subflow`, `llm`, `agent`, `condition`, …)
  raises `ToolLookupError(reason="not_an_agent_tool")`, with the message "'<name>' is a flow step, not an
  agent tool (fail closed)".
- **Every agent-tool lookup goes through it:**
  - the agent create and update API;
  - the static analyzer at publish (now a violation instead of a skip);
  - the runtime proxy;
  - the engine.
- **Saving a flow:** `FlowDefinition._validate_agent_node` applies the same set, so a flow with
  `tools: ["approval"]` is refused at save and at publish.

### 0c. The order-dependent vault error
- **Cause (reproduced):** the root `conftest.py` gives the whole session ONE vault file (`AGENTOS_VAULT_PATH`
  in the temp home). Some tests give each test a fresh master key (`AGENTOS_MASTER_KEY_FILE`) but keep the
  shared vault. If an earlier test stored a secret (webhook keys, from the server tests) with the session key,
  then `create_app`'s startup vault check in `test_flow_api_and_approval_2_1.py` fails with
  `VaultKeyMismatch`. Raw log: `raw/3.2-isolation-before-fix.txt` (4 errors, 1 failure in that order).
- **Fix:** an autouse **function-scoped** fixture in the root `conftest.py` that gives every test its own vault
  file and master key file *as a pair*, under a per-test temp dir.
  - Session- or module-scoped apps capture their vault when they're created, so they're unaffected.
  - Tests that set their own key or vault still override it.
  - The real `~/.agentos` guard stays.
- **Proof:** with `-p no:randomly`, run the same files in the failing order, the normal order and reversed order.

### 1. Cost per model call
- **The `llm_call` record** already has `prompt_tokens`, `completion_tokens` and `total_tokens`. It gains
  `cost_usd` and `price_source`.
- **Price lookup:** `agentos/usage/pricing.py`, `price_for(provider, model)` → `(in_per_1m, out_per_1m,
  source)`, in this order:
  1. **Admin override:** `security.prices` / `usage.prices` in `agentos.config.yaml`, as
     `{provider_or_model: {input_per_1m, output_per_1m}}`. Source `override`.
  2. **Registry:** an explicit `price` field on a provider entry (`{"input_per_1m", "output_per_1m"}`).
     Source `registry`.
  3. **Free and local:** providers tagged `free-tier`, `free` or `local` (Ollama) → **$0 explicitly**. Source
     `free_tier` or `local`.
  4. **LiteLLM's bundled `model_cost` map:** `input_cost_per_token` / `output_cost_per_token`. Source
     `litellm`. This is read from the installed package; no network fetch is triggered.
  5. **Otherwise:** `cost_usd = null`, `price_source = "unknown"`. **Never guessed.**
- **Honest note:** I have no verified price source offline, so the explicit registry table has `$0` only for
  free-tier and local entries. Paid entries aren't filled in by hand; they come from LiteLLM's map or the
  admin override. Rule 4: no invented numbers.
- **`cost_usd`** = `prompt_tokens * in / 1e6 + completion_tokens * out / 1e6`, rounded to 8 decimals. A
  failed attempt has no tokens, so it costs 0, but it's counted as an error.

### 2. Usage ledger
- **Key:** `(day UTC, flow_id, provider, model)` → `{calls, errors, fallbacks, prompt_tokens,
  completion_tokens, cost_usd, cost_unknown_calls, latency_ms_sum, latency_count}`.
- **Stores:**
  - **File:** `<project>/.agentos/state/usage_ledger.json`, under one asyncio lock, written atomically after
    each update.
  - **Mongo:** an `usage_ledger` collection with `$inc` upserts on a unique compound key.
- **Updated right after the `llm_call` event is appended**, in the same engine callback. "Atomic with the
  event" is impossible across two stores in file mode. If there's a crash between them, the ledger lags the
  events; `agentos usage rebuild` recomputes the ledger from all runs' `llm_call` events and replaces it. The
  events are the source of truth.
- **Errors and fallbacks:**
  - an `ok` record with failed attempts before it → `fallbacks += 1`;
  - `status: failed` → `errors += 1`;
  - `refused` (T-13, budget, run limit) → `errors += 1`, provider and model `"-"`.

### 3. Run limits (runaway protection, on by default, including $0 models)
- **Defaults:** `max_model_calls = 50` and `max_total_tokens = 300000` per run. A model call is one provider
  attempt, so failed attempts count too.
- **Where they're set:** globally and per flow, in the **admin-managed limits store**, next to budgets.
  - **Not the flow definition:** the prompt said "in its settings". If the limit lived in the flow itself,
    whoever edits the flow could raise it. Admin-only is the safer choice.
  - **A per-flow value can only lower the limit:** the effective limit is the minimum of the global and flow
    values.
- **Enforcement** is a guard called by the router **before every provider attempt**. Its per-run counters
  start from the run's existing `llm_call` events (on resume) and are updated from each record.
  - On a breach it raises `RunLimitExceeded("run limit exceeded: model calls 50/50")` (or tokens).
  - The engine writes a `run_limit_exceeded` event, and the run fails with that reason.
  - No further model call is made: the guard stays tripped.
- **Tokens are only known after a call,** so the call that crosses the token limit completes, and the next
  one is refused. The overshoot is at most one call's tokens.

### 4. Budgets
- **Kinds (USD):** `global_daily`, `global_monthly`, `flow_daily[flow_id]` and `provider_monthly[provider]`.
- **Stored with the run limits** in the admin store:
  - **File:** `<project>/.agentos/state/budgets.json` (atomic).
  - **Mongo:** a `budgets` document.
- **Editing them:** only through `PUT /api/v2/budgets`, which is **audited before it applies** (3.1,
  fail-closed 503) with the old and new values: numbers only, no secrets.
- **The check, before every provider attempt, in the same guard:**
  - **$0 known price:** always allowed. It adds no cost, so it's allowed even when a budget is spent.
  - **Paid or unknown price:** take the budgets that apply (global daily and monthly, the run's flow daily,
    the attempt's provider monthly).
    - If none apply, it's allowed.
    - If the price is unknown, it's refused: "budget applies but the price of `<provider>/<model>` is
      unknown; set a price in agentos.config.yaml (usage.prices)".
    - If spent ≥ limit for any of them, it's refused: `budget exceeded: <which>` (for example
      `budget exceeded: global_daily (5.00 USD)`).
- **No reservation.** I chose a check with no reservation; the upper bound of a call isn't known without a
  max_tokens cap.
  - **Consequence:** the last allowed call can overshoot by its own cost, and parallel runs by the calls in
    flight at the moment the budget is crossed.
  - **Bound:** ≤ (number of concurrent model calls) × (cost of one call). A test runs N parallel calls and
    checks the overshoot is ≤ N calls.
- **The fallback chain can't escape a budget.** After any budget refusal in a call, the router tries **only
  $0 providers** for the rest of that call; paid providers are skipped, recorded as `BudgetExceeded`
  attempts. If nothing $0 succeeds, the call fails with the first budget reason and the run fails (fail closed).
- **Spend totals come from the ledger:** today's and this month's sums, filtered by flow or provider, read
  fresh before each attempt.

### 5. API (same token auth; metadata only)
- `GET /api/v2/usage?group_by=day|flow|provider|model&since&until` returns grouped rows (calls, tokens, cost,
  errors, fallbacks, latency avg), plus `p50` / `p95` latency per provider computed from the window's
  `llm_call` events (capped at the last 2000 runs).
- `GET /api/v2/budgets` (budgets, run limits, and today's and this month's spend per budget with % used).
  `PUT /api/v2/budgets` is admin-only (the local token) and audited.
- `GET /api/v2/flows/{flow}/runs/{run}/usage`: the run's totals (calls, tokens, cost, unknown-cost calls) from
  its events.

### 6. UI
- **Watch → Metrics:** spend and tokens per day (grouped by provider, model or flow), top flows by cost,
  p50/p95 latency per provider, error and fallback rate, and budget bars with % used.
- **Overview:** a Spend card (today and this month vs the global budgets), shown when usage exists or a budget
  is set.
- **Run panel Steps:** each model-call step shows tokens and cost (or "price unknown"), and the panel shows
  the run total.
- **Settings:** a "Budgets and run limits" editor. It saves through `PUT /api/v2/budgets` (audited).

## Implemented: deviations from the design above
1. **Per-test vaults live inside the session temp home** (`<temp home>/per-test/vault-*`), not pytest's own temp
   folder. The existing guard test (`test_session_isolation_points_every_path_into_the_temp_home`) requires
   every AgentOS path to be inside the temp home, so this keeps that guarantee.
2. **The anchor check yields to an earlier chain break.** If the log is present and the chain itself breaks
   earlier (for example one entry deleted at seq 2), that more specific seq and reason are reported. The anchor
   reason ("deleted or rolled back") is used when the log is missing or otherwise verifies.
3. **A rejected extraction call doesn't swallow budgets or run limits.** A `quarantined_extraction` node
   re-raises `BudgetExceeded` and `RunLimitExceeded`, so the run fails with that reason instead of using the
   node's `on_invalid` defaults. An agent node checks the guard after the agent returns, in case the agent
   framework swallowed the refusal.
4. **The token limit counts finished calls.** The call that crosses it completes, and the next is refused, as
   designed. The test asserts `3000/2000` after two calls of 1500 tokens.

### Tests added (MOCK, `litellm.completion` replaced, fixed token counts 1000 in / 500 out)
- **Cost maths:** override, free-tier ($0), local Ollama ($0), unknown (null, never guessed), and the LiteLLM map
  when the installed map has the model.
- **Events and ledger:** `llm_call` events carry `cost_usd` and `price_source`; ledger totals = the sum of the
  events; `rebuild_rows` from events matches the live ledger exactly.
- **Run limits:**
  - model calls (on a $0 model) stops the run with "run limit exceeded: model calls 2/2", a
    `run_limit_exceeded` event, and no third call;
  - tokens (a per-flow limit that only lowers the global one) stops with "total tokens 3000/2000".
- **Budgets:** each type (global daily, global monthly, flow daily, provider monthly) blocks the call with no
  model call made; budgets for another flow or provider don't apply.
- **Fallback:** with `paid_a` over budget, the router skips `paid_b` (paid) and uses the $0 provider; with no $0
  provider, the run fails with the budget reason and no call is made.
- **Unknown price:** with a USD budget, the call is refused with the "set a price" message; local Ollama under
  the same budget is allowed.
- **Parallel overshoot:** 5 parallel runs with a budget below one call's cost all pass the pre-call check, the
  spend stays ≤ budget + 5 × one call (the documented bound), and the next run is refused.
- **API:** `/usage` group-by (`fallbacks` and `errors` counted), a 400 on a bad group-by, `PUT /budgets`
  audited (`usage.settings.update` with old and new values), a 400 on a negative budget, fail-closed 503 when
  the audit store isn't writable (the budgets don't change), 401 without the token, and `run usage` totals.
- **0a / 0b / 0c:** see the table and `test_review_gaps_3_2.py`:
  - delete log + head;
  - delete the log only;
  - roll back to an older genuine copy;
  - anchor missing or forged;
  - fresh install empty;
  - API verify;
  - step types refused at catalog, agent create and update, flow save, publish (analyzer) and the runtime proxy.
- **Changed tests:**
  - `test_mcp_2_5a.py`: a bare `http_request` is now refused as an agent tool.

## Gaps and known limits
- **Prices are estimates.** The explicit registry table has $0 entries for free-tier and local providers only.
  Paid prices come from the admin override or LiteLLM's bundled map, which can be stale; the provider's bill is
  the truth. Calls made before a budget existed with an unknown price count as $0 in the spend totals.
- **No reservation.** Parallel calls can overshoot a budget by at most the cost of the calls in flight (tested
  bound). A token reservation needs a max_tokens cap per call, which isn't done.
- **The ledger isn't transactional with the event in file mode.** After a crash between the two, it lags until
  `agentos usage rebuild`. The Mongo ledger and settings are **untested locally** (Docker wasn't running); there
  are no LIVE Mongo usage tests yet.
- **Scripted models aren't counted.** Run limits and budgets apply to calls through the router. A `custom_llm`
  (scripted test or embedded model) and MOCK mode make no router calls, so nothing is counted for them.
- **Latency p50/p95** come from a bounded scan (newest 500 runs).
- **Anchor limits (0a):** deleting the audit folder AND the anchor in the state store still looks like a fresh
  install, and an external anchor is still a follow-up.
- **No e2e for cost in the run panel.** The e2e server runs in MOCK mode with no real model calls, so the run
  panel's per-call cost and run total are only exercised through the event data the Python tests produce, not
  in Playwright.
- **README screenshots** predate the Metrics page and Spend card (the regenerated images were restored to the
  committed versions).

# 2.5a evidence: MCP servers (connect, discover, review, run through the AgentOS proxy)

Branch `feature/agentos-2.0-phase2.5a-mcp`, cut from `2.0` at `baaac22`. Every result below is **MOCK**:
local fixture MCP servers (stdio, or `127.0.0.1` HTTP), a scripted model, a recorded outbox, no real keys,
and no network beyond localhost. No LIVE run was made. Tests never touch `C:\Users\mujum\.agentos`: the
root conftest guard and the builder e2e temp home were in force for every run, and the resolved paths are
printed at the top of each log.

## (a) What changed

**Dependency**
- `mcp==1.30.0`, pinned in `pyproject.toml` and `requirements.txt`. It's the version CrewAI 1.15.41 already
  requires (`mcp>=1.30.0,<2`), so no new code enters the environment. The pip-audit gate passes with no
  finding for `mcp` and no new exemption.

**Backend**
- `agentos/mcp/catalog.py`:
  - **Names:** namespacing (`mcp.<server>.<tool>`; the model sees `mcp__<server>__<tool>`), normalisation to
    `[a-z0-9_]` with colliding names rejected.
  - **Hash:** sha256 of `[name, description, input_schema]` and a fingerprint of the launch target.
  - **Review status:** unreviewed, approved, changed or missing, plus merging a new discovery into the stored
    tools.
- `agentos/mcp/env.py`: the stdio child's environment is built from scratch.
  - **Windows:** `SYSTEMROOT`, `WINDIR`, `SYSTEMDRIVE`, `COMSPEC`, `PATH`, `PATHEXT`, `PROCESSOR_ARCHITECTURE` and
    `NUMBER_OF_PROCESSORS` are copied. `USERPROFILE`, `HOME`, `APPDATA`, `LOCALAPPDATA`, `TEMP` and `TMP` point
    into the per-server folder.
  - **Both platforms:** `PYTHONIOENCODING` and `PYTHONUTF8`, then the record's `env`, then `secret_env` resolved
    from the vault for that server only. `env` names starting `AGENTOS_` or matching a provider key variable are
    refused.
- `agentos/mcp/launcher.py`: the stdio transport, using the SDK's wiring with three differences:
  - the child gets exactly our environment;
  - one JSON-RPC message is limited to a maximum size;
  - stderr goes to the null device.

  On exit, the whole process tree is always ended (a Windows Job Object or a POSIX process group).
- `agentos/mcp/manager.py`:
  - **Lifecycle:** servers start on first use, stop when idle (default 300 s), and stop on shutdown.
  - **Limits per server and call:** a concurrency limit; a per-call timeout (default 30 s, max 120 s), after
    which the server is killed; an output cap (default 100 KB, truncated with a flag).
  - **HTTP:** the URL goes through `net_guard.check_url`, redirects are refused, and every request is checked
    again. SSE is refused.
  - **Server requests:** sampling, elicitation and roots are not advertised; any such request is refused and
    recorded.
  - **Run-time hash check:** before a call, the live tool hash is compared with the approved one, and a
    difference blocks the call.
- `agentos/flows/tool_catalog.py`: one tool lookup shared by the static analyzer, the proxy, the engine, the
  agents route and the publish route. It also holds the shared label rules:
  - an MCP tool without an admin description makes the agent's context untrusted from the start;
  - MCP outputs are untrusted with the configured confidentiality;
  - with an admin description, only property names and types reach the model.
- `agentos/flows/static_analyzer.py`, `proxy.py`, `engine.py`, `worker.py`, `models.py`:
  - **Lookup:** both sides use the catalog. Unreviewed, changed, missing or disabled MCP tools refuse publish
    and are rejected at run time.
  - **Publish:** records `analysis.mcp_tools`, the hashes of the MCP tools the flow uses. A run fails closed
    (`mcp_tool_hash_mismatch`) if a hash differs.
  - **Proxy:** MCP tools above read go through `sink_intent`, call, `sink_committed`. An intent without a commit
    is never retried.
  - **Events:** `mcp_tool_call` records the server, tool, duration, status, output bytes and a truncated flag,
    with no argument or output text.
- `agentos_server`:
  - the app creates the manager and stops all servers on shutdown, and the in-process worker passes the manager
    to the engine;
  - `routes_v2/mcp_servers.py`:
    - `GET /{name}/launch-preview`, `POST /{name}/enable`, `POST /{name}/discover`, `POST /{name}/tools/{tool}/approve`
      and `/revoke`;
    - a save never overwrites approvals, and a new launch target disables the server and puts its tools back
      under review;
  - `routes_v2/agents.py` accepts only approved MCP tools;
  - `routes_v2/flows.py`: publish uses the catalog.

**UI**
- `ui/src/pages/MCPServers.tsx`:
  - add a server, showing env names and vault names only;
  - enable, with the exact command line or URL and the env names shown first;
  - Discover;
  - a per-tool review panel: the description and schema as untrusted plain text, the side-effect class,
    per-argument "may be untrusted" toggles, confidentiality, and a replacement description;
  - Approve and Revoke, and a "changed, needs review" state;
  - rejected tool names are listed.
- `ui/src/pages/Agents.tsx`: the tool picker lists approved MCP tools as `mcp.<server>.<tool>` next to the
  built-ins.
- `ui/src/api/client.ts`: client functions for the new endpoints.

**Use case 08** (`examples/usecases/08-mcp-notes/`): an agent reads notes through the existing
`local_notes_server` (which now accepts an optional `NOTES_FILE`) and emails a digest to a pinned recipient.
The MOCK `run.py` also covers a poisoned description, a rug pull and shadowing. CI runs it through
`tests/ci/test_usecase_08.py`.

**Docs**: the README updates MCP from "Experimental" to verified in MOCK, and adds the MCP known limitations.

Also covered:

- a run fails closed on a hash mismatch;

## (d) Known gaps and anything skipped

- **DNS rebinding (HTTP servers):** the URL is checked and redirects are refused, but httpx resolves the host
  again when it connects. Pinning the IP is not done (agreed at CP1).
- **SSE:** not supported (deprecated in the MCP spec); discovery refuses it.
- **Platform mode:** a separate worker process gets its own manager; only the in-process worker is tested.
- **Sink rules:** the UI offers the side-effect class, per-argument "may be untrusted" and confidentiality.
  Allowlist-based sink rules exist in the API only.
- **Server-level events** (discovery, changes, refused requests) are stored under the run id
  `mcp-server-<name>`, until the 3.1 audit log.
- **Third-party servers:** MCP is verified only against local fixture servers. No public or third-party MCP
  server was run.
- **Changes from the CP1 plan:**
  - names fold `-` into `_`, so look-alikes collide;
  - the `FlowDefinition` model accepts `mcp.*` names and leaves the check to the catalog;
  - the analyzer counts only read-tool outputs, the same rule as for built-ins;
  - the launcher always ends the process tree, which fixed a grandchild orphan the test found;
  - the existing `agentos/mcp/__init__.py` docstring was extended, not replaced.
- **Fixed on the way:** use case 08 shows the notes demo server could write `notes.json` into the repo; it now
  honours `NOTES_FILE` (the default is unchanged).

## (e) How to reproduce

```powershell
$env:AGENTOS_MOCK_LLM="1"; .\venv\Scripts\python.exe -m pytest agentos/tests/test_mcp_2_5a.py agentos_server/tests/test_v2_mcp_api.py -q
.\venv\Scripts\python.exe examples\usecases\08-mcp-notes\run.py
cd ui; npx playwright test -c playwright.builder.config.ts e2e/builder-2.5a.spec.ts
```
In the app: open **Connect → MCP servers**. Add `notes` (stdio, `python`, with the path to
`examples/mcp_demos/local_notes_server/server.py` as the argument). Click **Enable…** and check the command,
then **Discover tools**, **Review** `list_notes` (write a replacement description) and **Approve this
version**. The tool now appears as `mcp.notes.list_notes` in the agent tool picker.

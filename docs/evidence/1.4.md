## (a) What Changed

Sub-Milestone 1.4 delivers end-to-end user interface and REST API management for AgentOS 2.0 core resources, backed by hardened NodeSpec schemas, 1.2 Storage ports (File and MongoDB), envelope-encrypted Credentials Vault, pure ASGI WebSocket security, and dynamic LiteLLM router fallback policies.

### 1. Backend REST API & Pure ASGI Security Middleware (`agentos_server/`)
- **Pure ASGI Security Middleware (`agentos_server/auth.py`):**
  - Replaced high-level Starlette middleware with a unified ASGI middleware handling both `"http"` and `"websocket"` scopes.
  - **DNS-Rebinding Defense:** Enforces strict Host header validation (`localhost` or `127.0.0.1` with port). Rejects invalid hosts with HTTP 400 (HTTP) or connection drop (WS).
  - **Token Authentication:** Generated on first start (`get_or_create_api_token()`), stored in secure directory outside repo (`~/.agentos/api_token`), and compared in constant time (`hmac.compare_digest`). Accepts `Authorization: Bearer <token>` or `X-AgentOS-Token`.
  - **WebSocket Hardening:** Strictly enforces Host header, Origin header against allowed local UI origins (`localhost`, `127.0.0.1` on ports 5173, 3000), and validates token via `Sec-WebSocket-Protocol: agentos.token.<token>`, echoing subprotocol `agentos.v1`. Missing/bad credentials or invalid origin immediately close with RFC-compliant WebSocket code `4401`.
  - **Fail-Fast Hardening:**
    - `MasterKey.load(create=True)`: Fails server startup immediately if master key file is corrupt or unreadable (no silent `generate()` fallback).
    - MongoDB: Fails server startup immediately if `AGENTOS_MONGO_URI` is configured but the MongoDB server is unreachable (no silent in-memory or file fallback).
  - **UI Port Startup Banner:** `print_startup_auth_banner(token, server_port)` dynamically detects whether production built assets exist (`agentos_server/static/index.html`); displays server port when built assets are present, and Vite port 5173 only in dev mode.
- **V2 Route Endpoints (`agentos_server/routes_v2/`):**
  - Modular, cleanly mounted under prefix `/api/v2`:
    - `agents.py`: CRUD for v2 agents. Validates configurations against `AGENT_NODE_SPEC.config_schema` (`additionalProperties: false`, rejecting `mcps`, `apps`, `memory`, `knowledge_sources`). Enforces fail-closed tool checks against declared `NodeSpec`s.
    - `squads.py`: CRUD for squads with member role assignments (`coordinator`, `worker`, `reviewer`).
    - `tools.py`: CRUD for custom tools. Preserves Python source code as text without executing it outside sandboxes; enforces read-only access on project tools (`origin="project"`).
    - `mcp_servers.py`: CRUD for external MCP servers (`stdio`, `sse`, `http`). Stdio servers and network endpoints are saved but **NEVER launched** automatically.
    - `vault.py`: Envelope-encrypted secret storage via `Vault` and `MasterKey`. The API **never returns plaintext secrets** (masked hint only, e.g. `sk-...abcd`).
    - `providers.py`: Provider catalog query (zero network calls), server-side SSRF-protected connectivity test (`/test-connection`), and persistent fallback policy editor (`/fallback`).
- **Synchronous Router Hook (`agentos/llm/router_factory.py`):**
  - Implemented thread-safe in-memory cache `_fallback_policy_cache` populated on startup and updated synchronously on `PUT /api/v2/providers/fallback`.
  - `build_router()` reads fallback order, timeouts, and enabled state synchronously without async event-loop deadlocks.

### 2. Frontend React/Vite UI (`ui/`)
- **Authentication Gate (`ui/src/components/AuthGate.tsx` & `ui/src/App.tsx`):**
  - Unauthenticated visits display a clean security card requiring the API token.
  - Automatically captures `#token=...` from the startup URL fragment into `sessionStorage` and sanitizes the address bar via `history.replaceState`.
- **Axios & WebSocket Helpers (`ui/src/api/client.ts`):**
  - Outgoing Axios requests automatically inject `Authorization: Bearer <token>` and `X-AgentOS-Token`.
  - `createRunStreamWebSocket(runId)` connects with subprotocols `['agentos.token.<token>', 'agentos.v1']`.
- **Resource Management Pages:**
  - `Agents.tsx`: Interactive agent creation with NodeSpec-declared tool picker, backstory, and role definitions.
  - `Squads.tsx`: Multi-agent squad creation with per-member role selectors.
  - `Tools.tsx`: Custom tool code editor; visual badges distinguishing project tools (`origin="project"`, read-only) from custom stored tools (`origin="stored"`).
  - `MCPServers.tsx`: Configuration for stdio/SSE/HTTP MCP servers with vault secret references and security notices.
  - `Providers.tsx`: Complete Provider Catalog, Credentials Vault (masked values, encrypted storage), on-demand Connectivity Testing, and drag/order Fallback Policy Editor.
- **Safe Markdown Rendering (`ui/src/components/SafeMarkdown.tsx`):**
  - Uses `react-markdown` with raw HTML disabled.
  - Custom `img` component that blocks external HTTP/HTTPS images to prevent tracking and exfiltration.

### 3. Use Case 02: Dynamic LLM Provider Fallback (`examples/usecases/02-provider-fallback/`)
- Demonstrates persistent fallback policy configuration, router prioritization, failover upon primary outage, and strict exclusion of disabled providers.
- Automated CI regression test in `tests/ci/test_usecase_02.py`.

## (d) Known Gaps and Limitations

1. **General SSRF Protection:** The `/api/v2/providers/test-connection` endpoint strictly limits custom base URLs to `localhost` and `127.0.0.1`, preventing intranet SSRF. Full arbitrary URL validation and egress gateway filtering are deferred to Phase 3 as scheduled.
2. **External MCP Execution Sandbox:** In Phase 1.4, MCP configurations are persisted and validated, but stdio command execution and SSE connection initiation remain dormant (spec principle 6). Sandboxed container execution will be provisioned in future milestones.
3. **Admin RBAC:** As documented in the Phase 1.4 design, authentication is controlled via the local master token until multi-user RBAC is introduced in Phase 3.

## (e) How the Owner Can Reproduce the Demo

1. **Start the AgentOS server:**
   ```powershell
   .\venv\Scripts\python.exe main.py
   ```
   Observe the printed startup authentication banner:
   ```text
   ======================================================================
   AgentOS Local Authentication Active
   One-time UI URL : http://localhost:8000/#token=<token>
   API Token       : <token>
   ======================================================================
   ```

2. **Open the Web UI:**
   Navigate in your browser to `http://localhost:8000/#token=<token>`.
   - Observe that the UI auto-authenticates, captures the token into `sessionStorage`, and immediately strips `#token=...` from the browser address bar.
   - Alternatively, open `http://localhost:8000/` without the hash and observe the Auth Gate prompting for the token.

3. **Navigate Core Resource Management:**
   - **Agents (`/agents`):** Click "New Agent", enter name/role/goal, select from NodeSpec-declared tools (`fetch_url`), and save.
   - **Squads (`/squads`):** Click "New Squad", select members, assign explicit roles (`coordinator`, `worker`), and save.
   - **Tools (`/tools`):** Inspect project tools (`origin="project"`, read-only) vs custom stored tools. Click "New Tool" to save custom Python code as text.
   - **MCP Servers (`/mcp-servers`):** Register an external stdio/SSE server referencing vault credentials. Notice the security badge confirming dormant execution.
   - **Providers & Vault (`/providers`):**
     - Store a secret: click "Store Secret" (`sk-test-live-key-123456`). Notice the table displays masked hint `sk-...3456` only.
     - Test connection: click "Test Connection" next to any provider.
     - Fallback policy: use the Move Up / Move Down buttons to reorder providers, toggle checkboxes to enable/disable, and click "Save Policy".

4. **Run Use Case 02 (Provider Fallback):**
   ```powershell
   .\venv\Scripts\python.exe examples/usecases/02-provider-fallback/run.py --mode all
   ```

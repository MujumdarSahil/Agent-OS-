## (d) Known gaps and decisions
1. **llm node is still a stub in the engine** (pre-existing: returns a mock completion). Per-node `model` is validated on save/publish, listed in `/node-specs`, and passed to agent nodes (CrewAI); the fallback chain for that per-node model was not verified by a test.
2. Security blocks (`SinkRuleViolationError`, `SSRFBlockedError`) and fencing errors are never routed to an `error_handler`; the run fails so blocks stay visible.
3. Subflows containing approval or wait nodes are refused (decision C); a waiting child run is backlog.
4. The `on_error` control dependency is always untrusted (a failure can be attacker-induced), so destructive sinks are not allowed after an error handler.
5. Static checks match allowlist CIDR entries only at runtime (needs DNS); statically a host is allowlisted only by name/wildcard, which is conservative (may refuse, never wrongly allow).
6. README: the MOCK quick start was verified on Windows only; macOS/Linux commands and Platform mode (Docker not running) are labelled as not run. Older README sections (v1 Quick Start with `main.py`, "ML & Training Capabilities", `ui/backend` paths) were not rewritten in this milestone and partly predate 2.0 (follow-up).
7. The builder's new branch selector has no Playwright test yet (the 7 existing builder specs pass).
8. The engine `_dispatch_node` signature was kept unchanged (an existing acceptance test patches it); the control label is passed through an engine-side map.

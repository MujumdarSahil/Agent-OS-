# 2.4e evidence: menu by purpose, Overview dashboard, readable flows, README with screenshots

Branch `feature/agentos-2.0-phase2.4e-dashboard`, rebased on `2.0` at `bab22cb` (after the vault fix,
[vault-incident-2026-11-18.md](vault-incident-2026-11-18.md)). Every result below is **MOCK**:
simulated model, fake network, recorded outbox, no real keys. No LIVE run was made for 2.4e.

## (a) What changed

**Backend**
- `agentos_server/routes_v2/overview.py` (new): `GET /api/v2/overview?window=24h|7d`. It is read-only, uses the
  same token auth as every other `/api` route, and any other window value returns 422. It aggregates runs, run
  events, flows, webhooks, the provider fallback policy, key presence (boolean only) and the circuit breaker.
  Untrusted text appears only inside a waiting approval's call.
- `agentos/llm/router_llm.py`: `cooldown_snapshot()`, a read-only view of the circuit breaker (seconds left and
  error class per provider).
- `agentos/flows/engine.py`: an unhandled `node_failed` event now carries `error_type` (the exception class name),
  so SSRF and sink blocks can be told apart from ordinary failures. This is additive metadata; labels and run
  logic are unchanged.
- `agentos_server/app.py`: `AGENTOS_SKIP_DOTENV=1` skips loading `.env` (used by the e2e server; the default is
  unchanged).

**UI** (`ui/src`)
- `App.tsx`: a sidebar grouped by purpose (Watch, Work, Build, Connect, Govern, System), with **Classic (v1)**
  collapsed. Every v1 page and route is kept; the v1 dashboard moved to `/classic/dashboard`. A footer card
  shows the mode (`Standalone · local only` or `Platform`) and the version.
- New pages: `Overview.tsx` (the home page), `Runs.tsx` (filters for flow, status and trigger), `Approvals.tsx`,
  `Triggers.tsx` (webhooks and schedules; secret paths and keys are never shown) and `SecurityLog.tsx`. Runs open
  in the existing results view via `/flows/<id>?run=<run_id>`.
- `flow/RunPanel.tsx`: the approval card and blocked-call list are shared components, and the panel can dock
  beside the canvas. Pinned values read **pinned in flow**, not "from <sink>", in both the approval card and the
  node inspector.
- `flow/builderModel.ts`, `flow/canvasParts.tsx`, `pages/FlowEditor.tsx`: a **Top to bottom** layout (vertical
  handles), opened by default when the left-to-right layout would fit below 60% zoom, with the results panel
  docked on the right. The toolbar wraps. "Publish refused" now appears once (the list heading reads
  "Why: N security violations").
- `flow/RunWidgets.tsx` and `flow/allRuns.ts` (new): approval and blocked-call widgets for any run, and a list
  of all runs built on the existing per-flow endpoints.

**Tests**
- `agentos_server/tests/test_v2_overview.py` (new, 8 tests); `agentos/tests/test_restructure_1_1b.py` (the pinned
  route table adds `GET /api/v2/overview`).
- `ui/e2e/management.spec.ts` (+4 tests: menu, Overview cards, empty Overview, list pages);
  `ui/e2e/builder-2.4e.spec.ts` (new, 4 tests: top-to-bottom layout before and after, small flow stays left to
  right, Overview on real data with approve and `?run=` link, README screenshots);
  `ui/e2e/builder-run-inspect.spec.ts` (pinned-in-flow and single "Publish refused" checks; its screenshots now
  go to `test-results` so the committed 2.4d evidence is never overwritten).
- `ui/playwright.builder.config.ts`: the e2e server never sees the real `~/.agentos`. HOME, USERPROFILE,
  AppData, `AGENTOS_VAULT_PATH`, `AGENTOS_MASTER_KEY_FILE`, `AGENTOS_API_TOKEN_FILE` and `AGENTOS_DATA_DIR` are all
  in a per-run temp folder. `AGENTOS_MASTER_KEY` is cleared, `.env` is not loaded, and the provider key variables
  from the developer's environment are blanked. The config refuses to start if any path points into the real
  `~/.agentos`, and prints the resolved paths with `AGENTOS_E2E_PRINT_PATHS=1`.

**Docs**
- `README.md` restructured for 2.0: a one-paragraph intro, Getting started (unchanged), What AgentOS can do
  (plus the Overview item), Model providers and fallback, Screenshots (7 images with captions), Known limitations
  (2.0), and More. The coverage badge is removed.
- `docs/v1/README_v1.md` (new): the v1 sections, moved verbatim (features, SWE, install, Quick Start code, project
  structure, demo, architecture, research, cybersecurity, ML/ModelHub, v1 UI, running examples, v1 limitations).
- `CLAUDE.md`: new section "Internal: test coverage (not public until 2.0 release)" with the coverage table and
  its command, moved from the README.
- `docs/SPEC_2.0.md`: Phase 3 numbering 3.1 to 3.6.
- `docs/images/*.png`: overview, flow-editor, run-inspect, approval, publish-refused, security-log,
  models-and-keys.

## Overview: data sources and hidden cards

| Card | Source |
|---|---|
| Needs you now (hidden when all zero) | waiting runs; blocked events since 00:00 UTC; providers cooling down (`cooldown_snapshot()`) |
| KPIs (24 h / 7 d) | `RunRecord.status`; blocked events; `llm_call` events (`latency_ms`, and `attempts` before an `ok` count as a fallback) |
| Live and recent runs | `RunRecord` and the last `ok` `llm_call` of each run |
| Waiting for you | `node_waiting` with `sink_args` (2.4d-fix card), from `GET …/runs/{id}/events`; decisions go through `POST …/approve` |
| Attacks blocked (last 5) | `tool_call_blocked`, `tool_call_rejected`, and `node_failed` from a sink rule, a pinned-argument override or an SSRF block; provenance from `blockedCalls()` |
| Model fallback chain | `/providers/fallback`, the `/providers` key flag (boolean), `cooldown_snapshot()` |
| Your flows, Getting started | flows and versions; vault or environment (boolean); runs; `approval_decision` events; webhooks |

Hidden because the data does not exist yet: spend, cost, budgets (3.2) and alerts (3.3). Refused publishes are
not stored, so the Security log lists run-time blocks only (3.1).

## (d) Known gaps and anything skipped

- **MOCK only.** No real-model run for 2.4e. The Overview's "model that answered" column shows "no model call"
  in the screenshots because the demo flows have no LLM node in MOCK.
- **Overview limits.** Provider health is per process and in memory (it resets on restart; in Platform mode it
  shows only the API process). Counts cover the newest 500 runs. SSRF blocks recorded before 2.4e lack
  `error_type` and are not counted.
- **The editor's status badge** shows "draft" for a flow that has a published version, because it reads the draft
  record. This is existing behaviour and is not changed here.
- **Minimap overlap**: with the results panel docked on the right, the minimap can cover the corner of the
  bottom-right node (visible in `raw/2.4e-after-uc07-tb-panel-open.png`). It can be hidden with "Hide minimap";
  hiding it automatically on narrow canvases is not done here.
- **The footer version** shows the package version (`v0.2.0`), as `/api/health` does.
- **Mode detection** reports Platform when the run store is Mongo or Redis is configured. Platform mode was not
  exercised in 2.4e.
- **Earlier builder runs** (before this branch fixed `playwright.builder.config.ts`) started their server against
  the real `~/.agentos`, and the webhook tests store signing keys in the vault, so those runs may have added
  entries to the owner's vault. The owner has since restored the vault from a backup.

## (e) How to reproduce

```powershell
$env:AGENTOS_MOCK_LLM="1"; .\venv\Scripts\python.exe -m pytest agentos_server/tests/test_v2_overview.py -q
cd ui; npx playwright test -c playwright.config.ts            # management (mocked API)
$env:AGENTOS_E2E_PRINT_PATHS="1"; npx playwright test -c playwright.builder.config.ts   # builder, temp home, MOCK
```
In the app: `python main.py` opens on **Overview**. Run use case 07 with the urgent ticket and it appears under
Waiting for you. Approve or reject it there, or open **Runs** to filter and open any run.

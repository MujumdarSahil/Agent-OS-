# 4.1b evidence: look-alike recipients (Part 0) + AgentDojo (Part 1)

Branch `feature/agentos-2.0-phase4.1b-agentdojo` (off `2.0` at b4518d1). The design decisions for Part 1 were
written before the AgentDojo implementation, as requested; sections (a) to (f) follow them.

## Design decisions (AgentDojo, written before implementation)

**D1. Dependency.** AgentDojo (https://github.com/ethz-spylab/agentdojo) is an optional, pinned benchmark extra:
`pip install -e ".[benchmark]"` installs `agentdojo==0.1.35`. A `pip install --dry-run` on the dev venv showed it only
ADDS packages (anthropic, cohere, google-genai, deepdiff, ...) and changes no installed version. It is never a product
dependency: nothing under `agentos/` or `agentos_server/` imports it. The adapter lives in `benchmarks/agentdojo/`.

**D2. The real AgentOS tool proxy, not a re-implementation.** Every AgentDojo tool is registered as a `ToolEntry` (with
an AgentOS `NodeSpec`) in an `AgentDojoCatalog` (a `ToolCatalog`). Every tool call the model makes goes through
`AgentOSToolProxy.invoke()` (`agentos/flows/proxy.py`), exactly as CrewAI agent tool calls do in a flow:
pinned-argument checks, the shared sink rules (`agentos/flows/rules.py`), context-label accumulation, and
sink_intent / sink_committed events in an isolated, temporary AgentOS event log. The entries are external tools
(server name `agentdojo`, like an approved MCP server), so the proxy's existing rule "external tool output is
untrusted" (`tool_catalog.context_after_tool_output`) applies unchanged. Execution is a small manager whose
`call_tool` runs AgentDojo's own `FunctionsRuntime.run_function(env, ...)`, so AgentDojo's environment and its
utility/security checks are untouched.

**D3. Labels.** The user task (the prompt) is trusted: it is the proxy's `agent_input_label`. Everything returned by
AgentDojo's environment tools is untrusted (provenance: the tool name). The agent's context label is the join of
everything it has seen; per the 2.0 label rule the model's output (its tool-call arguments) inherits that join. So
after the agent has read any environment data, every argument it passes to a sink is untrusted, and sink rules that
need trusted arguments refuse it: injected text cannot drive a recipient, an IBAN, an amount or a URL. This is
AgentOS's real, coarse (context-level) labelling. It also blocks some LEGITIMATE tasks whose recipient comes out of
data (e.g. "pay the bill in this file"). That cost is reported as the utility drop; value-level provenance (which exact
value came from where) is not invented here (2.1 backlog).

**D4. Which AgentDojo tools are sinks, and why.** Unknown tools fail closed (the catalog refuses them).

| Suite | Tool | AgentOS class | Must be trusted | Why |
| --- | --- | --- | --- | --- |
| workspace, travel | `send_email` | EXTERNAL_SEND | `recipients`, `cc`, `bcc`; `subject`/`body`/`attachments` untrusted only if all recipients are internal | sends data to a person |
| workspace | `share_file` | EXTERNAL_SEND | `email`, `file_id` | gives an outsider a file |
| workspace, travel | `create_calendar_event` | EXTERNAL_SEND | `participants` | invitations are sent to the participants |
| workspace | `add_calendar_event_participants` | EXTERNAL_SEND | `participants`, `event_id` | same |
| slack | `send_direct_message` | EXTERNAL_SEND | `recipient`, `body` | message to a person |
| slack | `send_channel_message` | EXTERNAL_SEND | `channel`, `body` | message to a channel (may include outsiders) |
| slack | `post_webpage` | EXTERNAL_SEND | `url`, `content` | publishes data on a web page |
| slack | `get_webpage` | EXTERNAL_SEND | `url` | the URL itself carries data out (as AgentOS's http rule: a URL chosen from untrusted data is refused) |
| slack | `invite_user_to_slack` | EXTERNAL_SEND | `user`, `user_email` | gives an outsider workspace access |
| banking | `send_money` | EXTERNAL_SEND | `recipient`, `amount` | moves money |
| banking | `schedule_transaction` | EXTERNAL_SEND | `recipient`, `amount` | moves money later |
| banking | `update_scheduled_transaction` | EXTERNAL_SEND | `id`, `recipient`, `amount` | redirects money |
| workspace | `delete_email`, `delete_file`, `cancel_calendar_event` | DESTRUCTIVE | the id | irreversible loss |
| slack | `remove_user_from_slack` | DESTRUCTIVE | `user` | removes access |
| banking | `update_password` | DESTRUCTIVE | `password` | account takeover |
| workspace | `create_file`, `append_to_file`, `reschedule_calendar_event` | WRITE | ids/times (content may be untrusted) | changes the user's own data |
| travel | `reserve_hotel`, `reserve_car_rental`, `reserve_restaurant` | WRITE | `hotel` / `company` / `restaurant` | commits the user to a booking |
| slack | `add_user_to_channel` | WRITE | `user`, `channel` | changes membership |
| banking | `update_user_info` | WRITE | every field | changes the account holder's identity data |
| all | every other tool (search, get, list, read) | READ | none | no side effect; its OUTPUT is untrusted |

**D5. A blocked call.** The proxy's refusal (`SinkRuleViolationError`, recorded as `tool_call_blocked`) is returned to
the model as a tool error and the AgentDojo task continues; this is how AgentDojo measures defenses (utility under
attack can survive a refused injection). Inside an AgentOS flow a blocked call fails the node instead.

**D6. Model and cost.** An AgentDojo pipeline element calls the AgentOS router (`AgentOSRouterLLM.call(messages,
tools, available_functions)`): provider fallback chain, cooldowns, and a 3.2 `RunGuard` per task (run limits and
budgets). Keys come ONLY from environment variables; AgentOS data/vault/key/token paths point at a temp folder and
`AGENTOS_FORBID_REAL_HOME=1` is set before anything is imported (same as `scripts/awib_live.py`). The attack is
AgentDojo's `important_instructions_no_model_name` (the router's answering model is not known in advance, so the
model-name variant does not apply). `scripts/agentdojo_run.py` prints the planned tasks and an estimated range of
model calls and needs `--yes`; `--limit N` runs a subset. Full runs are never in CI.

**D7. Metrics and output.** Per suite (workspace, slack, travel, banking) and defense (`none` = AgentDojo's plain tool
executor, `agentos` = D2): utility without attack, utility under attack, attack success rate (AgentDojo's own
`utility` and `security` checks; ASR = share of (user task, injection task) pairs where the injection goal was met).
Output is metadata only (counts, rates, provider names, number of blocked calls, errors by class name): never prompts,
model output, environment contents or keys. Results: `docs/evidence/4.1b-results.json` and `.md`.

**D8. CI.** A new, separate CI job `agentdojo-smoke` installs the `benchmark` extra and runs `benchmarks/agentdojo/tests`
with AgentDojo's ground-truth replay (no model, no keys): the adapter wires up, every suite tool is mapped, and one
injection (banking: send money to the attacker's IBAN) is blocked by AgentOS while the same replay without a defense
succeeds. The main CI job is unchanged (same skips, coverage gate and pip-audit scope).

**Part 0: look-alike destinations**

| File | Change |

| `agentos/flows/destinations.py` (new) | The shared check: NFKC; IDN punycode both ways; per-label script detection; built-in Latin/Cyrillic/Greek confusables table; `confusable` = mixed scripts in a label, an all-Cyrillic/Greek label made only of Latin look-alikes, or NFKC changed the text. | `agentos/flows/engine.py` | Approval card carries `destination_warnings`. `approve(..., confirm_lookalike=False)` refuses approving a card that has warnings without the confirmation. | `agentos_server/routes_v2/flows.py` | Approve body gains the optional `confirm_lookalike` (additive), which is also written to the audit details. A refusal returns 400. |

| `agentos/redteam/runner.py`, `benchmarks/awib/run.py` | Attentive approver heeds the warning; approve-all approves and confirms everything. Rows and summary carry both modes; headline table shows both. CI subset + the 5 S05b look-alikes (25 cases). |

Behaviour changes to note (no public v1 API change): `SecurityPolicy.is_internal_email` now refuses look-alike and
full-width addresses (before: plain lower-case string compare). The http allowlist compares IDN-normalised hosts.
A flow that PINS a look-alike recipient is now refused at publish. `FlowEngine.approve` has a new optional keyword.

AgentDojo detail: AgentDojo's attack constructor requires a known model key in the pipeline name even for the
`no_model_name` attack (which then discards it), so the pipelines are named `local-...`; nothing else uses the name.

- Confusables: a built-in Latin/Cyrillic/Greek table, not the full Unicode confusables data (Armenian, Cherokee, etc.
  look-alikes of Latin are caught only when mixed with Latin in one label).
- The run panel shows the warning on the inline approval card; past sink calls in the Steps tab are not re-annotated.
- Approve-all ASR stays 6.0% (S05b): an approver who confirms every warning defeats any approval. Pinning the
  recipient is the fix for that flow.
- AgentDojo D3 utility cost: coarse context labels also block legitimate sinks whose arguments come from data
  (banking replay: 33.3% utility without attack). Value-level provenance is 2.1 backlog.

## (e) Known gaps
1. Unsaved-changes protection covers browser navigation and in-app link clicks; programmatic navigation (none exists in the editor today) would not be intercepted. Moving to a data router (`createBrowserRouter` + `useBlocker`) is a possible follow-up.
2. Undo/redo covers graph edits (add, remove, connect, rename, config, pinned args, mapping, drag moves, layout); the flow name field is not part of the history.
3. Auto-mapping is a suggestion only; it does not change security rules (the publish gate still decides).
4. On a new flow the canvas starts at zoom 1 (no fit) so drops land under the cursor. Existing flows, auto-layout and a publish refusal re-fit the view (padding 0.2, never above 100%) once nodes are measured (polish commit; screenshots retaken).
5. Dragging between handles has no keyboard equivalent other than the drawer's "Connect output to…".

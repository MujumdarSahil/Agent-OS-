## (d) Known gaps and deviations
1. **Library versions differ from the CP1 plan:** `@xyflow/react` 12.12.0 (not 13.0.1) and `@rjsf/*` 6.11.0 (not 6.11.1), because the newer releases were less than two weeks old.
2. **Blocked-call view is verified with a synthetic stream, not a live runtime block.** Agent nodes are not executed in MOCK e2e (they need a scripted CrewAI LLM in the worker). Published non-agent flows do not produce runtime blocks.
3. **Use case spec location:** specs live in `ui/e2e/` (they need the UI's Node dependencies) and read the flow JSON from `examples/usecases/05-visual-builder/flows/`. Rule 11 asks for the spec under the use case folder; this is documented in the use case README.
4. **In-process worker:** a single loop with concurrency 1, Standalone only. Approval-resumed sinks still run inside the approve HTTP request (existing 2.1 behaviour). With no transport registry configured it uses `MockTransport`, so nothing is delivered.
5. Observed (not changed): `FlowWorker` constructed without a policy uses an empty `internal_domains`, while the app policy trusts `corp.local`/`internal.local`. The in-process worker passes the app policy, so it is consistent with the publish check.
6. Bounded loop edges render dashed with a "loop ≤N" label, but no e2e spec exercises loop editing.
7. No unit-test runner (vitest) in `ui/`; `flowGraph.ts`/`runModel.ts` are covered through the e2e specs only.
8. The `ui-e2e` CI job runs against the Vite dev server (React StrictMode on), not the packaged static build.
9. `npm audit`: the 10 pre-existing non-critical findings remain. The CI gate (critical) passes, and nothing was ignored or weakened.

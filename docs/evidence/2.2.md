## 1. Webhook Trigger (`/hooks/{secret_path}`)

### 1.1 Architecture & Routing
- Route is mounted at `/hooks/{secret_path}` (outside `/api`, requiring no API token).
- The secret path is cryptographically random (128+ bits), displayed to the user once upon creation or rotation, and stored as a SHA-256 hash in storage (`WebhookRecord.secret_path_hash`).
- Secret key for HMAC signing is 256 bits, generated cryptographically, and stored in the Credentials Vault under `secret_key_ref`.

### 1.2 Anti-Oracle Security Guarantees
- **Pre-lookup Gates:**
  - Client IP rate limit (120 req/min default per client IP) -> `429 Too Many Requests`.
  - Non-JSON `Content-Type` -> `415 Unsupported Media Type`.
  - Body size check (enforced during streaming with a 1 MB read cap) -> `413 Request Entity Too Large`.
  These checks run **before** looking up the path in storage.
- **Post-lookup Response Invariance:**
  - After pre-lookup validation, unknown path, disabled webhook, missing or malformed signature headers, stale timestamp (>300s window), replayed signature, and signature mismatch **all return an identical `404 Not Found`** (`{"detail": "Not Found"}`) to eliminate status-code and timing oracles.
- **Pinned Headers:**
  - `X-AgentOS-Signature: sha256=<64-character lowercase hex>`
  - `X-AgentOS-Timestamp: <integer seconds>`
  - Constant-time comparison using `hmac.compare_digest`.
- **Nonce Cache:**
  - 300-second sliding replay window.
  - Platform mode: `RedisNonceCache` using atomic `SET NX EX 300`.
  - Standalone mode: `InMemoryNonceCache` with automatic expiry (resets on server restart as documented).

### 1.3 Host Header Defense
- `AGENTOS_PUBLIC_HOSTS` allows an admin-configured list of hostnames/domains for webhook ingress.
- Crucially, `verify_host_header` enforces that public hosts are accepted **only** on `/hooks/*` paths. All other paths (including `/api/*` and UI `/`) strictly reject non-localhost traffic with `400 Bad Request`.

### 1.4 Security Labeling & Enqueueing
- Ingress payload is labeled `Integrity.UNTRUSTED` via Information Flow Control (IFC) labels.
- Run identifier uses a full `uuid4` (`run_<uuid4>`).
- Enqueues the latest published flow version into the queue backend.

## 2. Cron Trigger & Scheduler

### 2.1 Persistence & Data Model
- `ScheduleRecord` stored via `ScheduleRepository` across File and Mongo backends.
- Explicit `timezone` field (default `"UTC"`) with pinned parser `croniter==6.0.0`.
- Verified across Daylight Saving Time (DST) spring-forward and fall-back clock transitions.

### 2.2 Leader Lock & Misfire Policies
- **Leader Lock:**
  - Platform mode: `MongoLeaderLock` using Mongo server time (`$$NOW`) as a single shared clock with lease expiration and fencing tokens.
  - Standalone mode: `InProcessLeaderLock` for single-node deployments.
- **Misfire Policies:**
  - Supports `skip` (advances to current time without firing overdue ticks) and `fire_once` (fires exactly one run for missed ticks upon restart).
- **Storage Idempotency Key:**
  - Each tick generates an idempotency key: `f"cron:{schedule_id}:{int(tick)}"`.
  - Storage enforcement: unique sparse index on `RunRecord.idempotency_key` in MongoDB, and exclusive atomic file creation in Standalone File storage.
  - Verified: competing schedulers that both claim leadership for the same tick result in **exactly one run**.

## 3. Redis QueueBackend (Platform Mode)

### 3.1 Semantic Parity with In-Process Queue
- Implemented in `agentos/queue/redis.py` (`RedisQueueBackend`) with atomic Lua scripts for:
  - Job leasing (`enqueue`, `lease` with sorted set scores).
  - Heartbeat renewal (`renew_lease`).
  - Universal fencing verification across all states (`complete`, `fail`, `release_for_waiting` all raise `FencingTokenError` on stale leases).
  - Single shared clock semantics using Redis `TIME`.
  - Bounded retry tracking: `attempts` incremented on each lease; after `max_attempts` (default 3), transitions automatically to `dead_letter` status with `last_error="max_attempts_exceeded"`.
- Clean fail-closed behavior for unmanaged runs (`validate_lease(run_id, lease_id)` returns `False`).

### 3.2 Docker Compose & Automation
- `docker/compose.redis.yml`:
  - Pinned patch tag: `redis:7.4.2-alpine`.
  - Persistence enabled: `appendonly yes`.
  - Localhost binding only: `127.0.0.1:6379`.
  - Password required via `docker/.env.redis` (managed by `docker/redis-init.ps1` and `docker/redis-init.sh`).
- CI Integration: Added `redis-live` job in `.github/workflows/ci.yml` running against live Redis with password authentication.

- **Webhooks:**
  - `POST /api/v2/webhooks`: Create webhook (returns secret path and secret key once).
  - `GET /api/v2/webhooks`: List webhooks (secrets redacted).
  - `GET /api/v2/webhooks/{webhook_id}`: Retrieve webhook details (secrets redacted).

  - `PUT /api/v2/schedules/{schedule_id}`: Update schedule.

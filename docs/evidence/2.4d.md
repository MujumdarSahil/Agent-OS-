**Owner findings (fixed first):**
- **"Unsaved changes" on open.** A node click emits a drag-end position change with no movement, and the editor counted that as an edit. Now only a drag that actually moved a node, or a real edit, marks the flow dirty. Opening never does: auto-layout on open is display only.
- **Nodes cut off on open.** Opening now fits all nodes, with a 100% maximum and a minimum readable zoom of 0.35. Stored positions that overlap are replaced by auto-layout on open. The palette starts collapsed for existing flows (the **Add nodes** toggle opens it; it stays open for new flows), and the right inspector only appears when a node or edge is selected, so the canvas gets the width. The canvas re-fits when the results panel opens or closes.

**Run and inspect:**
- **▶ Run** sits next to Publish. It is disabled with a tooltip until a version is published, and its dialog runs the latest published version with input pre-filled from `sample_input`.
- **Results panel** along the bottom: resizable, collapsible, and live over the existing WebSocket. It shows status, total duration and final output.
- **Tabs:** Output; Steps (status, duration, and provider/model/tokens/fallback hops from `llm_call`); Logs (raw events); Security (blocked calls with reason and provenance chain, which opens by itself when a block appears).
- **Node inspector:** click a node on the canvas or a Steps row to see its exact input and output with labels. Untrusted values are plain text only (T-12).
- **Inline approval** shows the exact values with untrusted ones marked, using the same API as before.
- **History** lists every run of the flow with trigger, status and time; clicking one opens it in the panel.

## (d) Known gaps and decisions

1. **Unit tests:** the UI has no unit-test runner. The new `runModel.ts` derivations (`stepTimeline`, `nodeIO`, `runDurationMs`, `finalOutput`, `triggerOf`) are covered through the Playwright spec instead of the unit tests mentioned in the CP1 plan.
2. **Injection test.** No real runtime prompt-injection block can be produced in MOCK end to end without a scripted LLM in the server. The real-backend Security-tab test therefore uses the SSRF guard (an `http_request` to the cloud metadata address). The injection view (agent `tool_call_blocked` with provenance) remains covered by the existing synthetic-stream test in `builder-run.spec.ts`.
3. **Trigger for older runs.** Runs created before 2.4d have no stored trigger. The engine also rewrites `mission_name` once a run starts, so older webhook runs that have executed show as `manual`. The `run_started.trigger` the engine logs for worker-run jobs is still `manual`, which is unchanged. Passing `cron` there would change label semantics (cron inputs become trusted), so I didn't change it.
4. **Zoom floor.** A 7-step flow fits at about 0.38 zoom on a 1280×720 viewport. Text is small but every node is visible; zoom in with the controls.

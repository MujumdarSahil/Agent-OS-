## Design decisions

### D1. Part 0a & 0b: Agent setup & Flaky MCP test fix
- **0a. AGENTS.md**: Lightweight agent instruction guide (~40 lines) in repository root pointing to `CLAUDE.md` as the single source of truth, terminal setup `$env:AGENTOS_FORBID_REAL_HOME="1"`, git rules (feature branch only, never push 2.0/main, never open PR), evidence directories (`docs/evidence/<milestone>.md` and `docs/evidence/raw/`), and test commands.
- **0b. MCP Readiness Handshake**: `test_T6_output_cap_and_slow_tool_timeout_kill` failed intermittently under full-suite load with `BrokenResourceError` because `_RecordingSession` was initialized with `read_timeout_seconds=timedelta(seconds=self.call_timeout_s)` (2 seconds in test_T6). On heavily loaded machines (especially Windows), importing FastMCP and launching python subprocess takes >2.0s. When `session.initialize()` timed out after 2s, the stream was closed while the child process was still starting up. When the child process finally responded, `stdout_reader` threw `BrokenResourceError`.
  - Fix: Use `start_timeout_s` (default 30s) for `read_timeout_seconds` during `session.initialize()` and `self._list(session)`, and only update `_session_read_timeout_seconds` to `self.call_timeout_s` after the server successfully completes the handshake.
  - Fix: In `agentos/mcp/launcher.py`, catch `(anyio.ClosedResourceError, anyio.BrokenResourceError)` in `stdout_reader` and `stdin_writer` during transport teardown.

### D2. Review Item Data Model & Lifecycle (`agentos/review/models.py`)
- **ReviewItem**:
  - `id`: unique ID (`rev_...`)
  - `run_id`: associated flow run ID
  - `flow_id`: flow ID
  - `flow_version`: flow version integer or string
  - `node_id`: node ID whose output is being reviewed
  - `status`: `"pending"` | `"reviewed"` | `"skipped"`
  - `created_at`: float Unix timestamp
  - `input_data`: serialized node input dictionary/value
  - `output_data`: serialized node output dictionary/value
  - `labels`: list of security/provenance labels (e.g. `["UNTRUSTED"]`, `["SECRET"]`)
  - `verdict`: Optional `ReviewVerdict` (`"good"` | `"bad"`)
  - `reasons`: list of `ReviewReason` (`"wrong"`, `"incomplete"`, `"unsafe"`, `"made_up"`, `"formatting"`, `"other"`)
  - `corrected_output`: Optional text string written by reviewer
  - `note`: Optional note text
  - `reviewer_id`: User ID of reviewer
  - `reviewed_at`: Optional Unix timestamp
- **Lifecycle transitions**:
  - Item created by sampling rule or "Send to review" button in `"pending"` status.
  - Reviewer submits verdict: sets `verdict`, `reasons`, optional `corrected_output`, `note`, `reviewer_id`, `reviewed_at`, and moves status to `"reviewed"`.
  - Reviewer skips: sets `status = "skipped"`, `reviewer_id`, `reviewed_at`.

### D3. Storage Port & Adapters (`agentos/review/store.py`, `agentos/storage/mongo/review.py`)
- Following the pattern in `agentos/notify/store.py`:
  - `ReviewStore` wraps document stores: `items` and `sampling`.
  - File backend: `FileDocs(base / "review_items.json")` and `FileDocs(base / "review_sampling.json")`. Atomic writes with `atomic_write_text`, asyncio lock per file.
  - Mongo backend: `MongoDocs(db.review_items)` and `MongoDocs(db.review_sampling_configs)`.
  - Helper `review_store_for(storage)` automatically selects File or Mongo based on `storage.backend`.

### D4. Sampling Configuration & Engine Hook (`agentos/flows/engine.py`)
- **ReviewSamplingConfig** (per flow, audited on modification):
  - `flow_id`: str
  - `mode`: `"off"` (default) | `"all"` | `"percentage"` | `"rules"`
  - `percentage`: 1-100 (for percentage mode)
  - `rules`: list of matching condition strings:
    - `"failed"`: run finished with `RunStatus.FAILED`
    - `"fallback_used"`: an error handler fallback edge was taken (`state.handled_failures`) or an LLM provider fallback was used (`len(attempts) > 0`)
    - `"rejected_input"`: an extraction or validator node rejected input (`extraction_rejected` or `validator_rejected` event)
    - `"approval_rejected"`: a human approval was rejected (`state.error == "rejected_by_operator"`)
    - `"sink_blocked"`: a sink rule blocked execution (`tool_call_rejected` or `SinkRuleViolationError`)
  - `nodes`: list of node IDs to review (`empty` or `["*"]` / `["__final__"]` defaults to final output node; specific agent/llm/extraction node IDs allowed).
- **Engine execution hook**:
  - In `_update_run_status` when a run reaches terminal status (`SUCCEEDED`, `FAILED`):
  - If review store is configured, check flow's `ReviewSamplingConfig`.
  - If criteria match, sample target node(s) and create `ReviewItem(status="pending")`.
- **Manual "Send to review" button**:
  - API endpoint `POST /api/v2/review/send-to-review` allows sending any run or chosen node to the review queue on demand.

### D5. Roles, Capabilities, and Permissions (`agentos/access/permissions.py`)
- Capability addition: `"review"`
- Role capabilities matrix:
  - `viewer`: `{"self", "read"}` -> can see review queue, items, metrics.
  - `approver`: `{"self", "read", "review", "approve"}` -> can review (good/bad/reasons/corrected_output) and skip items.
  - `builder`: `{"self", "read", "review", "build"}` -> can review, configure sampling rules, and send runs to review.
  - `admin`: `{"self", "read", "review", "approve", "build", "admin"}` -> full access, including sampling config and JSONL export.
- Routes declared in `agentos_server/permissions_table.py`:
  - `GET /api/v2/review/items`: `read`
  - `GET /api/v2/review/items/{item_id}`: `read`
  - `POST /api/v2/review/items/{item_id}/verdict`: `review`
  - `POST /api/v2/review/items/{item_id}/skip`: `review`
  - `GET /api/v2/review/sampling/{flow_id}`: `read`
  - `PUT /api/v2/review/sampling/{flow_id}`: `build`
  - `POST /api/v2/review/send-to-review`: `build`
  - `GET /api/v2/review/metrics/{flow_id}`: `read`
  - `GET /api/v2/review/export`: `admin`
- Audit:
  - Review verdict submission: audited (`actor=user`, action=`review_verdict`).
  - Sampling rule changes: audited (`actor=user`, action=`review_sampling_update`).
  - Export: audited (`actor=user`, action=`review_export`).

### D6. Label Handling, Plain-text Safety, and Output Isolation
- The review screen displays inputs and outputs using the same secure formatting as the run panel:
  - Values carrying the `UNTRUSTED` label are rendered as sanitized plain text only (never interpreted as HTML or executed).
  - Security and provenance labels (`UNTRUSTED`, `SECRET`) are visibly highlighted.
- Corrected output isolation:
  - A corrected output text provided by a human reviewer is strictly stored in the `ReviewItem` record.
  - It is NEVER automatically fed back into any running or scheduled flow run.
  - It is exposed only via the Review UI and the admin test export.

### D7. Quality Metrics
- Calculated per flow and per version:
  - `reviewed_count`: count of items with status == `"reviewed"`
  - `good_count`: count of items with `verdict == "good"`
  - `bad_count`: count of items with `verdict == "bad"`
  - `good_percentage`: `round((good_count / (good_count + bad_count)) * 100, 1)` if reviewed > 0 else 0.0
  - `top_bad_reasons`: list of `{"reason": reason, "count": count}` sorted descending by frequency for items where `verdict == "bad"`.
- Display locations:
  - Flow Card: quality badge showing `% good` and total reviewed.
  - Metrics page: dedicated flow quality card with top bad reasons breakdown.
  - Overview page: summarized quality widget shown when flows have reviews.

### D8. Admin JSONL Export
- Format: JSON Lines (`application/x-ndjson`), one line per reviewed item:
  - Fields: `flow_id`, `flow_version`, `node_id`, `input`, `output`, `verdict`, `reasons`, `corrected_output`.
- Secret Redaction:
  - If values or fields carry the `SECRET` label, their values are replaced with `"[SECRET redacted]"` by default.
  - If the admin passes query parameter `include_secrets=true`, the raw secret values are included, and the audit log records `include_secrets=true`.

- List view:
  - Filter bar: Flow selector, Status filter (`all`, `pending`, `reviewed`, `skipped`), Verdict filter (`all`, `good`, `bad`).
  - Table of items: Flow, Version, Node, Created timestamp, Status, Verdict, Actions.
- Review screen / modal:
  - Left/top pane: Node Input and Output with visual label badges.
  - Controls:
    - **Good** button (shortcut: `G`)
    - **Bad** button (shortcut: `B`)
    - Reasons multi-select checkboxes: `wrong`, `incomplete`, `unsafe`, `made_up`, `formatting`, `other`.
    - Corrected output text area.
    - Note text area.
    - **Save and next** button (shortcut: `N`).
    - **Skip** button.
- Flow Settings Review section:
  - Radio selector for sampling mode: `off`, `all`, `percentage`, `rules`.
  - Percentage input (1-100).
  - Checkboxes for matching rules: `failed`, `fallback_used`, `rejected_input`, `approval_rejected`, `sink_blocked`.
  - Node selection: default final output vs chosen nodes.

# 3.3 evidence: alerts and notifications (plus three follow-ups from the 3.2 review)

Branch `feature/agentos-2.0-phase3.3-alerts`, cut from `2.0` at `671edf4` (3.2 merged). All results are **MOCK**
unless labelled LIVE. "Real email" in this report means a real SMTP conversation with a **local** aiosmtpd test
server on 127.0.0.1; no message leaves the machine.

## Design decisions (written before the implementation)

### 0a. Billing plan per provider (free | paid)
- **Storage:** `UsageSettings.billing_plans: {provider: "free" | "paid"}`, next to budgets and run limits (file
  `budgets.json`, Mongo `usage_settings`). A provider not listed keeps today's behaviour.
- **Price order with a plan:** `free` -> $0, source `plan_free`, and this wins over everything, including an admin
  price override (the admin says this account is not billed). `paid` -> the free-tier tag is ignored: admin
  override -> registry price -> LiteLLM -> unknown. `local` stays $0 (a local model has no bill).
- **One place:** `UsageContext.price()` (used by the budget guard and by the cost on every `llm_call`). The plans
  are cached on the context and refreshed whenever settings are read or written, so the synchronous guard needs
  no I/O.
- **API:** `PUT /api/v2/providers/{name}/billing-plan {"plan": "free" | "paid" | "default"}`, provider must be in
  the registry, audited (`provider.billing_plan.update`, old and new plan) before it applies, 503 if the audit
  entry cannot be written. `PUT /api/v2/budgets` keeps the stored `billing_plans` when the payload has none (the
  budgets editor cannot wipe them by accident). `GET /api/v2/providers` gains `billing_plan`.
- **UI:** Models & keys gets a "Billing plan" select per provider (Default / Free plan / Paid).

### 0b. Live Mongo tests for the usage store
- New `agentos/tests/test_usage_mongo_live.py`, skipped without the Mongo URI the mongo-live CI job already sets.
  Tests: 50 parallel `add()` calls on one row and on several rows -> exact totals; `rows(since, until)`
  filtering; `rebuild_rows()` over a Mongo storage with runs and `llm_call` events equals the ledger built
  incrementally; settings round-trip including `billing_plans`.

### 0c. fetch_url makes a real GET
- **Path:** the proxy's `fetch_url` branch calls `HttpRequestTransport.request("GET", url, timeout_s=10,
  max_bytes=100_000)` from `agentos/flows/net_guard` (SSRF checks on every hop, connect to the checked IP,
  max 3 redirects, each re-checked). The transport is `transport_registry["fetch_url"]` when given (tests),
  otherwise a new `HttpRequestTransport(policy.http_allowlist)`.
- **No credentials, no cookies:** only the model's `url`; no headers from the model; the httpx client is created
  per request and never keeps cookies; URLs with userinfo are refused by `check_url`.
- **Output:** text `"[HTTP <status>] <body>"` (body cut at 100 KB, `[truncated]` appended), still UNTRUSTED (the
  existing `context_after_tool_output` rule is unchanged).
- **Event:** `fetch_url` with metadata only: `mode` (`live` | `mock`), `status`, `bytes`, `truncated`, `host`
  (from the CHECKED target), `redirects` count. The body never goes into an event.
- **Refusals:** an SSRF refusal appends `tool_call_blocked` (counts as "attack blocked") and raises; a timeout or
  connection error returns an AgentOS-written error text to the model and records `status: "error"`.
- **MOCK:** with `AGENTOS_MOCK_LLM=1` and no injected transport, a canned body
  `"[HTTP 200] (mock fetch_url: no network request was made)"`, event `mode: "mock"`.

### 1. Notification channels
- **Model** (`agentos/notify/channels.py`), name `^[a-z0-9][a-z0-9_-]{0,39}$`:
  - `email`: `host`, `port`, `security` (`starttls` | `ssl` | `none`), `allow_insecure_local`, `username`,
    `password_secret` (vault secret NAME), `from_address`, `allowed_recipient_domains`, `alert_recipients`
    (who gets alerts), `use_for_flows` (at most one email channel; this is the one `send_email` uses).
  - `slack`: `webhook_secret` (vault secret NAME), `display_channel` (label only), `internal` (admin flag that
    lets untrusted text go to it).
  - `enabled` on both.
- **Secrets are write-only:** create/update accept `password` / `webhook_url` and store them in the vault as
  `notify.smtp.<name>` / `notify.slack.<name>`; the record keeps only the secret name. No API returns a value;
  a GET returns `password_set` / `webhook_set` booleans.
- **Email validation at save AND at send:** `security: none` only with `allow_insecure_local: true` and host
  `localhost`/`127.0.0.1`/`::1`. The SMTP host is resolved and every address goes through
  `net_guard.blocked_reason`: loopback passes only for `allow_insecure_local` channels; any other blocked range
  (private, metadata, ...) only if the host/IP matches the admin `notifications.smtp_allowlist` in
  `agentos.config.yaml` (config file = admin; a separate list from `http_allowlist`, so allowing an SMTP relay
  does not open HTTP to it). We connect to the CHECKED IP; TLS verifies the certificate against the configured
  hostname (`ssl.create_default_context()`). STARTTLS is required when configured: a server without STARTTLS
  fails the send (no plaintext fallback). `smtplib` only, no new runtime dependency.
- **Slack validation at save AND at send:** `https://hooks.slack.com/...` exactly (scheme https, host exactly
  `hooks.slack.com`, default port, no userinfo), sent with `HttpRequestTransport` (redirects re-checked, 10 s,
  small size cap). Payload `{"text", "unfurl_links": false, "unfurl_media": false}`.
- **Test stand-in:** a constructor argument of the Slack sender used only by tests (not reachable from config or
  API) points it at the local HTTP Slack stand-in with a test-only allowlist.
- **Send test:** `POST /api/v2/notify/channels/{name}/test`, audited (`notify.channel.test`, outcome). Errors
  shown to the user are AgentOS-written (`"SMTP authentication failed"`, `"the server refused a recipient"`,
  `"TLS certificate verification failed"`, `"Slack answered HTTP 404"`, ...). No server response text is echoed.
- **Audit:** `notify.channel.create|update|delete|test` with metadata (name, type, host, port, security, flags,
  secret NAME, counts). Never a secret value.
- **Policy sync:** after every channel change the server updates `security_policy.slack_channels`
  (`{name: internal}`); the static analyzer and the runtime rules read it (below).

### 2. Real sending from flows
- **Server transport registry:** `send_email -> ChannelEmailTransport`, `send_slack -> ChannelSlackTransport`
  (installed at startup when no registry is set; tests that set one keep it). Transports may define
  `async avalidate(args)` (called BEFORE `sink_intent`, so a refused send leaves no intent) and `async asend(...)`
  (the engine and proxy prefer it; SMTP runs in a thread). `retry_safe = False` on both.
- **No email channel:** `send_email` stays simulated: the result is `{"status": "simulated", "reason":
  "simulated: no email channel configured"}`; it is in `sink_committed` and the run panel shows it. Never a
  silent "sent".
- **Unknown Slack channel:** refused (rule violation), never simulated: the channel argument is a trust decision.
- **Email hardening (`agentos/notify/email.py`, used for flows, alerts and the test button):** CR, LF and other
  control characters in `to`/`subject` refused; `to` is one address or a list, max 20, with the existing
  `normalize_and_validate_recipients` rules (no display names, no comma lists); `allowed_recipient_domains` when
  set; subject <= 200 chars, body <= 100 KB; `from`/`sender`/`reply_to`/`headers`/`cc`/`bcc` in the args are
  refused (From always from the channel); `Message-ID: <sha256(idempotency_key)[:40]@agentos.invalid>`;
  `text/plain; charset=utf-8` only.
- **Exactly-once as far as SMTP allows:** `sink_intent -> send -> sink_committed` as today. New: a pending
  intent of a `retry_safe = False` transport is never re-sent. Direct sink node: `resume()` moves the run to
  `uncommitted_sink_needs_review` (today only agent nodes did); agent tool: the proxy refuses with the same
  reason (today it re-sent). The Message-ID lets a receiver de-duplicate in the remaining window (crash after
  the server accepted but before `sink_committed`).
- **`send_slack` node** (EXTERNAL_SEND, `recipient_arg = "channel"`): args `channel`, `text` (<= 3000 chars).
  Rules (shared rule engine: analyzer, engine, proxy):
  - `channel`: trusted (pinned or a trusted value) AND the value must be a configured Slack channel
    (condition `slack_channel_configured`; at publish checked when pinned, at runtime always);
  - `text`: untrusted allowed only if the channel is configured with `internal: true`
    (condition `text_internal_channel_only`, same shape as the email body rule);
  - `channel` joins `RECIPIENT_ARGS`, so a declassified enum can't pick a channel (2.5b rule).
  - **Escaping for every text (trusted or not):** `&`, `<`, `>` -> `&amp;`, `&lt;`, `&gt;` (no `<!channel>`,
    no `<url|label>`), plus a zero-width space after `@` in `@channel`, `@here`, `@everyone` (defense in depth);
    unfurling off.
  - NodeSpec, contract test, static rules, engine sink path, proxy path, agent tool name, UI palette entry.
- **Label rules for `to`/`body` are unchanged.**

### 3. Alerts
- **Rule types:** `attack_blocked` (security block events: `tool_call_blocked`, `tool_call_rejected`, a
  `node_failed` that `is_security_block`, plus "publish refused" from the publish route), `run_failed`,
  `approval_waiting` (param `minutes`, default 30), `provider_down` (an `llm_call` whose attempts show a provider
  skipped in cooldown = circuit open, or `status: failed` = every provider failed), `budget_exceeded`
  (`budget_exceeded` and `run_limit_exceeded` events), `audit_broken` (`verify()` status `broken`, including
  anchor missing; checked at startup and on every `GET /audit/verify`).
- **Rule fields:** `id` (= type, one rule per type), `enabled`, `channels` (names), `cooldown_min` (default 15),
  `params`. Defaults for every type are created on first start with `channels: []`: alerts are still recorded
  (status "no channel") but nothing is sent until the admin picks a channel.
- **Cooldown per rule + target** (target = flow id, provider name, or `audit`): inside the window the existing
  alert's `count` goes up and `last_seen` moves; nothing new is sent.
- **Alert text is written by AgentOS from metadata only:** rule title, flow id, run id, count, an AgentOS reason
  from a fixed table keyed by event kind / error class (for example "a sink rule blocked a send"), and a link
  `<ui_base_url>/runs/<run_id>` (`notifications.ui_base_url`, default `http://127.0.0.1:8000`). Every identifier
  is kept only if it matches `^[A-Za-z0-9_.:-]{1,64}$`, else `other`. NEVER event `reason`/`error` text, tool
  names chosen by a model, argument values or any payload: rule-violation reasons can contain attacker-chosen
  values (a recipient, an attempted value).
- **Where evaluated:** the server wraps `storage.events` with an observer (all events appended through the
  server process: in-process worker, approvals, routes). Evaluation never raises into the engine.
- **Outbox (persistent, file and Mongo):** one entry per (alert, channel), id = idempotency key
  `sha256(alert_id|channel)`. States `pending -> sending -> sent`; on error `retrying` (backoff 30 s, 60, 120,
  240) and `failed` (dead letter) after 5 attempts. An entry found in `sending` at startup was maybe sent: it
  becomes `failed` with "delivery uncertain (server stopped during send); not resent", so a restart never
  double-sends. Email alerts carry a `Message-ID` from the same key.
- **Delivery worker:** one asyncio task that sleeps until the next due entry or until woken by a new alert (no
  fixed polling interval), also holding the `approval_waiting` timers (scheduled at `node_waiting` + N minutes;
  re-scheduled at startup from waiting runs). Stopped on shutdown. Tests call `process_due(now)` directly.
- **Alerts page:** fired alerts with per-channel status (sent / retrying / failed / no channel), count, last
  seen, acknowledge (audited `alert.acknowledge`). Overview "Needs you now" gets `unacknowledged_alerts`.

### 4. API (same token auth; admin = local token until Phase 3 RBAC; metadata only)
- `GET/POST /api/v2/notify/channels`, `PUT/DELETE /api/v2/notify/channels/{name}`,
  `POST /api/v2/notify/channels/{name}/test`
- `GET /api/v2/alerts/rules`, `PUT /api/v2/alerts/rules/{id}` (audited `alert.rule.update`)
- `GET /api/v2/alerts?status=&rule=&acknowledged=&limit=`, `POST /api/v2/alerts/{id}/acknowledge`

### 5. Things in the prompt I changed or narrowed (safer option)
- **`send_slack` channel:** besides "untrusted text only to an internal channel", the channel value itself must
  be trusted and configured; an unknown channel is refused, not simulated.
- **SMTP allowlist** is its own `notifications.smtp_allowlist`, not `http_allowlist` (see 1).
- **Loopback SMTP** is reachable only by an `allow_insecure_local` channel; that flag is admin-only and audited.
- **Agent `send_email` re-send after a crash** (existing proxy behaviour) is a real double-send risk once SMTP is
  real; fixed here (see 2).
- **Alerts from a separate `agentos worker` process** (Platform mode) are not evaluated: the observer lives in
  the server process. Listed in gaps.
- **SMTP exactly-once is impossible:** a crash after the server accepted the message and before
  `sink_committed` leaves an intent that is never resent automatically; the receiver can de-duplicate on
  Message-ID. Known limitation in the README.

## Implemented: deviations from the design above
1. **Simulated `send_email` with invalid arguments** (found by the builder e2e): the use case 05 approval flow maps
   the whole webhook payload (an object) into `to`. MockTransport used to "send" that. With no email channel the
   send is still simulated, but the result now says `"simulated: no email channel configured; a real email channel
   would refuse these arguments"`. Header injection (control characters) and From/Cc/Bcc/headers overrides are
   refused even when only simulated. With a channel configured, every check refuses the send. Test:
   `test_simulated_send_still_refuses_injection_and_reports_invalid_arguments`.
2. **Non-text bodies** (a mapped object, a number) are sent as JSON text instead of being refused.
3. **Event type for the agent "never resend" hold** is `sink_needs_review` (not `tool_call_blocked`), so it is not
   counted as an attack.
4. **Default transport changed on purpose**: the server's `send_email` / `send_slack` now use the channel
   transports (no channel = simulated, labelled). `test_worker_uses_mock_transport_when_none_configured` became
   `test_worker_uses_channel_transports_when_none_configured`.
5. **Snapshot tests updated for intended additions** (each one asserts an exact list): the v2 route table
   (`test_restructure_1_1b.py`: +10 routes; the v1 route table is unchanged and still passes), the agent tool
   options (`test_calculator_3_1.py`: + `send_slack`), Overview `needs_you` (`test_v2_overview.py`:
   + `unacknowledged_alerts`).

## Gaps and known limits
- **LIVE Mongo** not run locally (Docker Desktop did not come up). The 0b tests and the Mongo notify store run only
  in CI; `MongoDocs` (channels, rules, alerts, outbox) has **no LIVE test** yet.
- **No real third-party delivery**: email was verified only against a local aiosmtpd (plaintext and STARTTLS with
  a test CA), Slack only against a local HTTP stand-in. No message was sent to a real mail provider or to Slack.
- **Alerts from a separate `agentos worker` process** are not evaluated (server-process observer only).
- **`send_email` failure before DATA** (connection refused) also leaves an intent without a commit: the run fails
  and a resume waits for review, even though nothing was sent (conservative).
- **Cooldown is not atomic across processes**: two events at the same instant may create two alerts.
- **Alert retention**: the file backend keeps the newest 5000 alerts; Mongo keeps everything.
- **Slack**: incoming webhooks only; the AgentOS channel name is a label.
- **One ad-hoc smoke run** of `create_app` outside pytest read (did not write) the real `~/.agentos` key and token
  files; their modification times were unchanged. Every test run used the isolated test home.
